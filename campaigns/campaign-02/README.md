# Campaign 02 — automated waves (2026-08-30)

The full S-layer battery — 25 tasks (5 senses × 5 stacks) — run as
automated waves: one sense on five stacks simultaneously, five agents
in parallel, one task per agent, no operator questions during the run.
Wave order: conduit → pressmark → errand → brim → quire.

## Layout

- `briefs/<sense>/<stack>.md` — the 25 wishes, stack-pinned.
- `materials/<sense>/` — task fixtures (see below), byte-identical for
  every stack of the sense.
- `world.Dockerfile` — the campaign layer over the base world image
  (`../../world.Dockerfile`).
- `genmat/` — the deterministic generator for the brim JPEG fixtures
  (Go stdlib, fixed seed): the same two files on every platform.

## The machine

The binary is built twice from the release tag, compared
byte-for-byte, with the version stamped in and the SHA-256 recorded in
the wave journal. It is mounted read-only into every world at
`/usr/local/bin/punchtape`.

## The world image

Base (`../../world.Dockerfile`): the five toolchains (python, go, rust,
cpp, js) plus the linters (pyflakes, staticcheck, clippy, cppcheck,
eslint). Campaign layer (`world.Dockerfile`):

- apt: g++/make/cmake/pkg-config (C/C++ builds), redis-server (task
  daemons in the world), libgraphicsmagick++1-dev, libhiredis-dev,
  libyaml-dev, libmd4c-dev;
- Node.js under /opt/node + typescript/@types/node/eslint; js task
  dependencies in /run/node_modules (resolved by walking up from
  /run/task/**);
- rustup stable + clippy (the distro rustc is too old for modern
  crates);
- python: Pillow, numpy, redis, plus the brief-pinned PyYAML /
  Markdown / Jinja2 / pydantic / python-slugify;
- C++ headers vendored: inja, nlohmann/json (no apt packages);
- the Go module cache (goldmark, yaml.v3, go-redis/v9, google/uuid)
  and the crate cache (tokio full, image, the errand set: redis /
  uuid / serde, the quire set: serde_yaml / comrak / tera);
- offline modes: GOPROXY as a file proxy over the module cache,
  GOSUMDB=off, GOTOOLCHAIN=local, GOFLAGS=-mod=mod,
  CARGO_NET_OFFLINE=true.

## Task worlds

One container per task (the recipe and the honesty rules are in
`../README.md`). Build the world for a wave from the campaign layer
plus the JS resolution layer (`world-js.Dockerfile`) — every stack
benefits, and js tasks resolve bare imports from the run directories
without library fallbacks. Stage the brief directory read-write and
mount the task materials separately, read-only, at
`/run/task/materials`. Task directory: `brief.md`; the
repository, docs, and campaign files are never mounted. Smoke checks
before the first wave of the day: a go build from the module cache, a
cargo build offline, a cpp build against inja+libyaml, python imports
of every pinned library, node resolution from /run/node_modules — all
with the network off.

## Materials (identical within a wave)

- brim: `bordered.jpg` (250×250, an even 4 px black frame, a live
  middle) and `clear.jpg` (510×350, no margin) — generated by `genmat`
  with a fixed seed, byte-identical on every stack;
- pressmark: the three-record storage (first — a picture and tags,
  second — empty lists, third — plain and oldest) plus entity/index
  templates in each stack's engine syntax (jinja2 / html/template /
  tera / inja / nunjucks), equivalent in their substitutions;
- quire: data.yml (a pair of keys), about.md without a header, post.md
  with one, style.css — byte-identical; the index template in each
  stack's engine (j2 / tmpl / tera / inja / ejs);
- conduit, errand: no external material (the echo stand / redis live
  in the world).

## Host hygiene

Before every wave: reconcile the host (CPU count, free memory), kill
every stale container, verify the binary digest. After every task:
export the ledger and state, `chown` the task directory back from
root, remove the container. OOM (exit 137) is an environment fact:
recreate the world with a larger cap and record the case.
