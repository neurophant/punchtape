Работай в /run/task через фреймворк. Бриф (brief.md) — единственный
ввод; прочти его целиком и прочти AGENTS.md (самодок фреймворка) до
первого вызова.

- Начни с: punchtape next "$(cat brief.md)" — весь бриф и есть
  пожелание; первый вызов создаёт экземпляр и закрепляет цель.
- Крутись в next/submit, пока ответ не принесёт строку VERDICT — эта
  строка и есть конец. Подавай предложения файлами delta.yaml, каждый
  файл кончается хвостом: # TOKENS n/a
- ОДИН прогон: не перезапускай, не удаляй экземпляр. Отказ — одна
  строка: почини предложение и подай снова.
- Коды 3/4 (вопросный батч / эскалация): выбор делает оператор, а не
  ты; получи его решение и проведи его следующей подачей.
- Материалы в /run/task/materials — входы только для чтения:
  копируй из них, не правь их и не подавай файлы материалов внутри
  подач кода (повторный прогон застрянет на монтировании только для
  чтения).
- Держи спеку стройной: переформулируй в 2–3 capability —
  пользовательские черты пожелания, не дерево осколков; таблица
  кейсов закрепляет поведение брифа и ничего больше — никаких
  сценариев, которых бриф не просил, никакой позолоты; авторская
  проза — один текст на capability.
- Вердикт требует авторской прозы: когда тесты зелёные, подай
  kind: feature с текстом на каждую capability (все тексты одной
  подачей), живыми словами — человеческая спека часть готового.
  Заложи на это подачи.
- Подавай таблицы целиком: таблица кейсов — одна подача (режь только
  если действительно не лезет, никогда на осколки); починки —
  заменой строк, не новыми частичными таблицами.
- Каждый элемент прогона — ОДНА команда: строка "cmd args" или список
  argv [cmd, args...] — плоский многошаговый скрипт не строка;
  долгие помощники и ожидания живут внутри собственных команд строки
  (однострочник шелла); всё, что команда оставила живым, убивается в
  конце строки; фоновые помощники закрывают наследованные каналы
  вывода (>/dev/null 2>&1).
- Не читай внутренности фреймворка: всё, что машина считает нужным
  сообщить, она печатает сама, а AGENTS.md — её единственная
  документация. Копаться в установленном коде машины, её пакетах и
  кэшах запрещено; работать с машиной — только через команду
  punchtape.
- Ничего кроме подач и продукта: никаких побочных проектов в
  /run/task, никаких правок вне продукта и delta.yaml, никакой
  работы вне каталога задачи.
