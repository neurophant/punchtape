# Etalon: brimfeat — the JSON answer on the standing tool

The meaning's yardstick, written into the campaign before any run:
every hand of brimfeat, in every stack, is judged against these same
lines — the instrument is one; no product, no hand and no judge
forms it. Each line is one requirement of the brief with the run
that proves it.

1. `brim detect --json <picture>` prints exactly one JSON object on
   one line — {"top":N,"bottom":N,"left":N,"right":N} with plain
   integers — and nothing else on that line — proof: run on the
   material's pictures, read the line whole.
2. The JSON numbers are the tool's own answers: the object's four
   values equal the bare form's four numbers on the same picture —
   proof: both forms run, the numbers compared.
3. Without --json nothing changes: the bare four numbers, the law to
   the letter — proof: the bare form run on the material before and
   after, the answers identical.
4. The knob law rides unchanged in both forms: --band and
   --threshold keep their ranges and behave the same in JSON as in
   bare form — proof: the knob matrix run in both forms, the objects
   compared to the bare numbers.
5. Honest refusals in both forms: a missing file, a non-JPEG, a bad
   knob value, an extra path, an unknown flag — the same plainly
   worded refusal, on stderr, with the JSON form adding nothing —
   proof: each provoked once in each form, the messages read.
6. The standing law is not broken: the old behaviors — the four
   numbers, the band and threshold law with their material answers
   ("4 4 4 4", "0 0 0 0", the band cuts of the material), the
   JPEG-only refusal, the repeat-to-the-letter determinism, the
   clean tree — all stand as before — proof: the old probe matrix
   run green and the tree checked clean after.
7. The verdict stands over the grown corpus: the new behavior beside
   the old, every old row still green — proof: the corpus's standing
   verdict line over the corpus version grown.
