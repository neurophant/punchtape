punchtape — контракт

Ты только что запустил punchtape — и он напечатал эту страницу:
в этом каталоге ещё НЕТ инстанса. Ничего не существует и ничего
не создано. ЧТОБЫ НАЧАТЬ: создай файл .punchtape/wish.md и положи
в него желание человека дословно, затем запусти punchtape снова —
этот запуск родит инстанс, навсегда зафиксирует цель и запишет
стоящие файлы зоны.

ВЫЗОВ, всегда. Один вызов, без аргументов: `punchtape`. Терминал
получает ровно одну строку — следующее действие с именем файла,
которого оно касается. Всякий дальнейший ответ — файл этой зоны:
state.md держит стоящее и инструкцию next:, report.md — факты
последнего прогона.

ЦИКЛ, после рождения. Подай документ → его строки исполнятся →
чини код или строки до зелёного → скопируй corpus.yaml байт-в-байт
в inbox.yaml и запусти: эта подача — акт завершения, машина
записывает вердикт. После state.md показывает вердикт и любой
дрейф с него. В каждой точке строка терминала и next: в state.md
говорят ровно то, что делать сейчас.

law:wish      Желание человека, дословно, в .punchtape/wish.md.
              Следующий запуск рождает инстанс и фиксирует цель
              навсегда; слот мёртв после рождения. Нет желания —
              нет рождения; ничего другое инстанс никогда не
              создаёт. При рождении машина нумерует каждую
              непустую строку желания W1..Wm по порядку файла —
              номера фиксированы навсегда: байты желания больше
              не меняются.

law:document  Вся работа — один документ (форма ниже). Скопируй
              template.yaml, отредактируй, подай как
              .punchtape/inbox.yaml. Подача СЛИВАЕТСЯ по id:
              перечисленное поведение добавляется, или его голова
              заменяет стоящую, а его строки сливаются по run —
              тот же run заменяется ЦЕЛОЙ строкой, новый run
              дописывается, непоименованные строки стоят.
              Требования сливаются по id так же; поданный список
              not-a-requirement или artifacts заменяет стоящий
              целиком. Неперечисленное стоит нетронутым;
              подмножество поведений — нормальная подача. Число
              подач не влияет на цену: перечисленные байты едут
              один раз, неизменённые строки не переотправляются.
              Удаление — только явный remove-список существующих
              id — поведений или требований; увольнение
              требования обязывает ту же подачу снять все covers
              на него. notes — свободный текст, никогда не
              интерпретируется.

              Реестр учитывает желание: требования называют
              занимаемые строки брифа W-диапазонами; поведения
              называют доказываемые требования в covers; строки,
              которые ничего не требуют, помечаются
              not-a-requirement — собственные слова строки
              цитируются дословно рядом с причиной; artifacts
              объявляют выходы работы. Каждая строка несёт явный expect —
              rc, out или files — и каждое поведение несёт хотя
              бы одну строку: строки — всё, что поведение
              доказывает.

law:paths     Каждый путь — expect-файлы, глобы scope, artifacts —
              относительно рабочего корня. Абсолютные, «..» и
              убегающие написания отвергаются.

law:done      Подача байт самого корпуса (corpus.yaml, скопированный
              в inbox.yaml без изменений) — акт завершения,
              записывающий вердикт. Вердикт требует: каждая строка
              зелёная на текущих отпечатках; желание учтено
              целиком — каждая W-строка внутри диапазона
              некоторого требования или помечена
              not-a-requirement —; каждое стоящее требование
              названо в covers стоящего поведения, несущего
              строки; и ни одного непокрытого исходника;
              объявленные артефакты — подписанные выходы
              документа. Размер корпуса решает размер желания —
              не вкус. Всё, что меньше, значит «ещё нет» —
              report.md называет дыры.

law:your-tree Строки и сборка исполняются в твоём рабочем дереве,
              от его корня, с PATH и HOME, а сверх них — с
              собственным ENV-файлом дерева, если он есть (по
              одному KEY=VALUE в строке, экспортируется как
              написано), — больше ничего не передаётся. Зови
              нужное проекту явным относительным путём
              (./tool, bin/helper) и включай такие файлы
              в скоуп поведения. Сборка, если объявлена, идёт
              ПЕРВОЙ; её отказ останавливает строки этого
              прогона. Убирай за собой в самих командах:
              оставленные файлы меняют дерево.

СКОУП — от чего зависит строка. Скоуп поведения перечисляет его
файлы глобами от корня («**» пересекает каталоги). Строка
перезапускается, если: изменились её байты, изменились файлы
скоупа её поведения, изменилась среда или она никогда не
исполнялась. Неизменный скоуп — строка больше не исполняется
никогда. Поведение со строками БЕЗ скоупа перезапускается каждый
прогон: строкам всегда нужен скоуп. Файлы вне всех скоупов
делятся в state.md: объявленные артефактами документа стоят под
«artifacts (declared)», остальные — непокрытые исходники —
покрой их скоупом или объяви, иначе они держат вердикт.

ОТКАЗЫ. Отказанная подача остаётся в inbox.yaml — байты документа
не пишутся ничего; сама машина журналирует отказ как собственный
факт, state.md его считает. report.md называет поле, факт и id
закона. Почини названное место в том же файле и запусти снова —
отказ стоит один прогон, ничего не теряется. Красные строки стоят в report.md, сгруппированы по
причинам.

ФОРМА ДОКУМЕНТА (скопируй template.yaml и правь):

  notes: [{text: свободный текст}]
  build: "./build all"
  remove: [old/thing, R2]
  requirements:
    - id: R1                 # R, затем буквы, цифры и точки
      brief: [W1..W4, W9]    # строки желания, которые занимает требование
  not-a-requirement:
    - lines: [W5]
      quote: "заголовок"      # собственный текст помеченных строк, дословно
      reason: заголовок, а не требование
  artifacts: [out/**]        # объявленные выходы работы
  behaviors:
    - id: tool/build         # сегменты [a-z0-9-] через /
      name: одна строка
      prose: что получает пользователь и почему
      scope: [src/**]        # файлы поведения, глобы от корня
      covers: [R1]           # требования, которые доказывает поведение
      rows:
        - run: "./tool src out"
          expect: {rc: 0, out: "contains: ok",
                   files: {out/built.txt: "contains: done"}}

Каждое поле expect необязательно, но хотя бы одно из rc, out,
files обязано стоять — пустой expect отвергается; rc отсутствует =
ожидается 0; значение с префиксом «contains: » матчит подстроку,
без него — точные байты. run — одна команда: строка оболочки или
argv-список. W-диапазоны — W<n> или W<a>..W<b>, по возрастанию,
через запятую — они именуют нумерованные строки желания и ничего
другое.

ФАЙЛЫ ЗОНЫ. contract.md (эта страница; contract-ru.md,
contract-zh.md — её зеркала) template.yaml | wish.md inbox.yaml —
пишешь ты | corpus.yaml стоящий корпус | state.md состояние,
дрейф, карта брифа, следующий шаг | report.md последний прогон
или отказы | knowledge.md заметки и уроки | spec/ страница на
каждое поведение | journal/ канон — не редактировать никогда |
cache/ tmp/ — принадлежат машине.
Одна запись стоит вне зоны: AGENTS.md рабочего корня несёт
помеченный блок машины (её крючок обнаружения), поддерживаемый
целым каждым запуском; байты вне блока не трогаются никогда.
