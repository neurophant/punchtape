# 词汇表
[English](GLOSSARY.md) · [Русский](GLOSSARY.ru.md) · **中文**

机器词汇的词典——读者在它的区文件、终端行与契约中可能遇见的每一个词。原则：只要读者可能不懂一个词，它就在这里得到解释，用平实的语言，配一个例子或一个类比；`→` 指向本词典内的相关词条。机器自己的封闭词汇很小——法则 id、行状态（绿、红、过期）、愿望行号（W1、W2、…）——下文其余一切解释的是这个词汇以及紧邻它的世界。

A

**Accept**（接受）— 机器对一份通过了每条规则的文档所做的事：其规范字节与合并后的行为落入对象库，提交记录落入一个新日志纪元，现状移动，提交槽被消费。与 → refusal 相反。例：携带一个新行为的 `inbox.yaml` 被接受；下一条终端行点名的是下一步而非这次接受——接受活在 `state.md` 的计数器里。

**AGENTS block**（AGENTS 块）— 机器的发现钩子：工作根 `AGENTS.md` 内一个带标记的块，以 `<!-- punchtape -->` 与 `<!-- /punchtape -->` 为界，每次运行整体确保。内容相同则不触碰；内容有变则整体自我替换；无标记的外来文件在末尾获得该块。标记之外的字节从不被触碰。类比：图书馆藏书的书牌——贴在封皮内侧，书页不属于图书馆员。→ working tree。

**Argument refusal**（参数拒绝）— 二进制对任何携带除单独 `--version` 之外参数的启动所回答的那一行：拒绝点名法则（调用不取参数），且是那次启动的全部动作——不触碰状态，退出码 1。→ the call。

B

**Artifacts**（artifacts）— 文档声明的产出：相对根的通配，命名工作预期留下的文件。不被任何 scope 覆盖、也不被任何 artifacts 通配命中的树文件是 → uncovered source；被 artifact 命中者在 `state.md` 的 「artifacts (declared)」 之下。例：`artifacts: [out/**]` 声明构建的输出目录。→ uncovered sources。

**Behavior**（行为）— 一个命名的可见行为单元：一个 id（`[a-z0-9-]` 段以 `/` 相连，如 `tool/build`）、一行名字、作者的 → prose、可选的 → scope、可选的 → covers、以及至少一个 → row。id 是合并键：重复同一 id 的提交替换行为的头部并合并其行。有行而无 scope 的行为每次运行都重跑——诚实地永远 → stale。

**Birth**（诞生）— 创建实例的动作：日志目录的一次原子 `mkdir`（并行运行中恰好一个赢家——输家作为普通运行继续）、愿望的字节作为日志第一条记录进入对象库、愿望槽被消费、区的现状文件由正典写出。除它之外没有任何东西能创建实例。类比：在一条全新带子上打出第一个孔。→ wish slot、→ instance。

**Brief map**（概要映射）— `state.md` 一行上的愿望记账：`brief: <claimed>/<lines> lines; requirements <n> standing, <k>
covered; not-a-requirement: <m>`，其后是逐一拼写的每个标注，以及未覆盖的愿望行（若有）。与裁决的愿望门禁读的是同一套算术——绝无两个真相。→ wish coverage、→ registry。

**Build**（构建）— 语料可选的声明命令（一条 shell 行）。它成立时，每次运行中最先执行，先于任何行，服从与行相同的执行法则。非零退出、挂过期限、或从未启动的构建对整个运行为红：每一行都被冻结——什么都不执行，除构建自己的日志化事实外什么都不动。在文档中声明构建即替换现有命令；字段缺失则保留。→ machine run。

C

**The call**（调用）— 机器的全部接口：`punchtape`，无参数，工作根或其下任意位置。终端那一行之外的每个回答都是 → zone 的一个文件。→ terminal line、→ exit code。

**Canon**（正典）— 机器把自己作为法则印出的一切的唯一内嵌源：英文契约（基底与标尺）、俄文与中文镜像（数据，结构完整）、文档模板、示例、法则映射与环境规则。区的契约文件与模板在诞生时由它生成；一个会对机器撒谎的示例会让构建失败。→ contract、→ law-map。

**Canonical bytes**（规范字节）— 一份文档的唯一官方拼写：先严格解码进模型，再规范编组（两空格缩进、map 键排序、字段按声明顺序、命令作者的拼写原样保留）。同一内容的两种拼写是同一个内容——机器只比较、只记录规范字节。例：重新缩进的 `inbox.yaml` 与原件是同一份提交。

**Clean environment**（干净环境）— 机器每条命令所见的基础：恰是正典声明的名字——`PATH` 与 `HOME`——取自运行机器的 shell，加上区的 → pins，别无其他。实际传递的集合，连同机器版本、架构与内核版本，构成 → environment hash。

**Completion act**（完成动作）— 签收：一份 `inbox.yaml` 载有恰好等于现状语料规范字节的内容（实践上：`corpus.yaml` 逐字节复制进 `inbox.yaml`）。不是文档——是槽把语料送回。运行继续其寻常步骤，由 → verdict 步骤决定：每道门禁绿——记录一份裁决；差任何一点——报告点名空洞。作为独立于提交的、自己的日志化事实计数。→ machine run。

**Contract**（契约）— 机器的全部法则作为一个文本（区内的 `contract.md`），在 → first contact 时整份打印到终端。五条带 id 的法则——`law:wish`（愿望槽及其编号行）、`law:document`（唯一格式及其合并法则）、`law:paths`（仅限相对根路径）、`law:done`（完成动作与裁决的门禁）、`law:your-tree`（执行环境）——外加 scope 法则、拒绝法则与文档的形状。俄文与中文镜像携带同一法则集；英文文本为准。

**Corpus**（语料）— 现状文档：每次被接受的提交之后的行为、登记簿与构建命令的现状。其规范字节以 `corpus.yaml` 存活（一个生成的映像，每次运行修复）并存在于裁决的签名之内。每个行都绿时语料为绿——裁决的依据。→ corpus version。

**Corpus version**（语料版本）— 被接受提交的计数器：每次接受加一。裁决记录它宣告时的版本；`state.md` 的裁决行两者都点名，而下一条指令区分「当前版本上立着一份裁决」与「全绿，下一步是完成动作」。→ verdict。

**Covers**（covers）— 行为的证明主张：该行为的行所代表的 requirement id 清单。一个 cover 必须命名提交合并后仍然现存的要求；退役一个要求就要求同一次提交清掉它的每一处覆盖。没有行为覆盖的现存要求是 → orphan requirement，并挡住裁决。

D

**Deadline**（期限）— 机器每条命令运行于其下的 300 秒上限——每一行与构建一视同仁：到期时整个进程组被杀，事实拼写为 `timed out after 5m0s`。它是挂起的终结者，绝不是慢工作的裁判：机器限制的是一条命令可以挂多久，从来不是代理可以干多久。→ process group、→ red build freeze。

**Digest**（摘要）— 机器的身份单位：精确字节的 sha256，十六进制。同字节——同摘要；异字节——以压倒性概率得出不同摘要。摘要调和机器的世界：文件摘要、scope 指纹、证明、对象地址、裁决的签名。面向人的拼写截取前 12 个字符。类比：指纹——不是手指本身，但足以命名它。→ object store、→ proof。

**Document**（文档）— 唯一的输入格式，一份严格解码的 YAML 文件：`notes`、`build`、`remove`、`requirements`、`not-a-requirement`、`artifacts`、`behaviors`（含 `rows`）。文档是整张表或表的一个子集：未列出的，即不改变。→ canonical bytes、→ merge、→ validation。

**Drift**（漂移）— 树在现存裁决之下移动了的派生事实：一次运行在裁决成立时有行站红（历史点名该运行与红行键），或一个活行为的当前 scope 指纹异于裁决记录的指针（状态页上的 `scopes moved` 标记）。没有任何东西监视任何东西——两个标记都只是日志化事实与新指纹上的算术。之后一次没有红行的运行将漂移治愈，同样记名于历史。→ verdict history。

E

**Environment hash**（环境哈希）— 命令所见之物的指纹：机器版本、`GOOS/GOARCH`、内核版本、以及实际传递的有序 `NAME=value` 集（干净基底加固定）。它进入每一枚 → proof：一个会话改变了环境就移动了证明——行随之过期，绝不假绿。

**Epoch**（纪元）— 日志流的一个编号文件（`journal/` 下的 `epoch-NNNNN.yaml`）：记录追加进活纪元，每条记录是行首 `---` 分隔符后的一个 YAML 文档。提交在其记录落地前轮转日志流——每个提交的记录活在属于自己的纪元里；已是新的纪元保持不变（轮转从不堆叠空文件）。加载时按编号顺序读每个纪元。→ journal、→ torn tail。

**Exit code**（退出码）— 调用唯一的二元回答：0——机器干成了活（红行是数据，不是错误）；1——调用没有发生（区损坏、无法加载的日志、无法落地的机器所属写入）。

**Expect**（expect）— 行对命令留下之物的期望：`rc`（精确退出码；缺省 = 0）、`out`（stdout：精确字节，或 `contains: ` 前缀后的子串）与 `files`（运行后读取的相对根路径，同样两种匹配写法）的任意组合。至少一个字段必须成立——空的 expect 被拒绝。比对是纯粹的：任何地方都没有解读。

F

**First contact**（首次接触）— 工作目录处或其上方没有 `.punchtape` 的一次启动：机器打印整份契约并以 0 退出，不创建任何东西。终端输出整页仅此一例——文件通道尚不存在，于是法则本身就是回答。

**Fold**（折叠）— 由过去重建现在：日志的全部记录从最老到最新重放进 → standing——诞生定死目标，提交移动语料，运行设定行事实，裁决成立，拒绝与完成各自计数。同样的记录永远折叠出同样的现状。类比：从头重放一条打孔带——带子是真相，机器的记忆是派生的。

G

**Goal**（目标）— 实例定死的愿望：愿望的字节作为内容寻址对象，在诞生时连同摘要一起记录——永远不可变。状态页显示摘要与对象的地址；每条愿望行与每个标注引文都派生自这些字节，所以编号不会漂移。

**Green**（绿）— 一种行状态：它跑过，且每个期望都成立（破损事实清单为空）。其 → proof 仍然成立的绿行被 → kept green——不重新执行。每个行都绿时语料为绿；只有又绿又新鲜的语料才能合上一份裁决。

H

**Hash cache**（哈希缓存）— `cache/hashes.yaml`：树遍历的 `(path, size, mtime)` → 摘要加速器，每个条目带着它所说的摘要法则标签。被动过的文件诚实重算；损坏或缺失的缓存读作空；异种标签的条目退出重算，绝不撒谎。每次运行落盘一次。删掉它，下一次运行重算出同样的数字——加速器，从来不是真相源。→ scope fingerprint、→ tree walk。

**Holes**（空洞）— 没有要求跨度也没有标注认领的愿望行：`state.md` 把它们拼写出来（`uncovered brief lines: W…`），裁决在它们面前拒绝（`not yet — the wish lines W… stand uncovered by any
requirement or marker`）。解析不了的范围拼写，或愿望宇宙之外的编号，一概不认领——它点名的行仍是诚实的空洞。→ wish coverage。

I

**Inbox (the submission slot)**（收件槽，即提交槽）— `inbox.yaml`，区唯一的输入文件。它在，意味着一次提交在等待：一份待解码、待校验、待接受的文档——或 → completion act——或一次什么也不改变的 → refusal（字节留下，作者修好被点名的位置再运行）。它不在，是寻常状态。进入机器的一切都经由这一个文件。

J

**Instance**（实例）— 机器的一个任务：一个工作根、它的区 `.punchtape`（日志、对象、视图、槽）与根中的 AGENTS 块。诞生一次，永不死亡；真正的新任务是全新目录里的新愿望。→ birth、→ zone。

**Journal**（日志）— 唯一的真相源：`journal/` 下只追加的记录流；每次提交开启一个新纪元。六种记录——诞生、提交、运行、裁决、拒绝、完成——各携带恰好属于自己的载荷，任何地方都没有墙上时钟：次序是记录在流中的位置，身份是它的字节。同一段历史的日志在每台机器上字节相同。其他每个区文件都是它的生成映像。→ fold、→ standing。

K

**Kept green**（保持绿）— 所录证明等于当前证明的绿行：该行不执行、不读取、不触碰——它录下的绿继续成立。机器的全部经济所在：未变的输入分文不花。→ proof、→ stale。

**Knowledge**（知识文件）— 区的记忆文件 `knowledge.md`：每个被接受提交的每条笔记恰好一次（编号，其 → tags 在其行上）、标签索引、以及按原因分组的 → lesson 条目。由日志生成；笔记本身从不被解读。

L

**Law ids**（法则 id）— 契约的五条命名法则，每次拒绝的词汇：`law:wish`、`law:document`、`law:paths`、`law:done`、`law:your-tree`。每次拒绝必引其一——被点名的规则与契约永远说着同一件事。→ refusal。

**Law-map**（法则映射）— 正典的对表：每条校验规则绑定到契约印出的一条法则，每条被引用的法则都是契约印出的。凡被执行的皆有印出；凡被印出的皆被执行。

**Lesson**（教训）— 一次被修好的红，以纯数据固定：原因类别、行键、破损事实、该行之前与之后的字节（之前的字节凭摘要从日志的行为对象找回）、以及两个运行编号。由运行记录自己写出——任何模型的 token 一个不花。原因已有教训的当前红会从 `state.md` 被指过去。例：某行在运行 4 因 `exit: got 1, want 0` 而红，运行 5 转绿——教训携带前后两份行与两个编号。

M

**Machine at birth**（诞生时的机器版本）— 诞生记录携带的机器版本：实例自己的起源事实，由状态页打印（`machine at birth:`）；记录里缺它的实例显示 `(not recorded)`。该版本也进入环境哈希，所以新机器诚实地作废旧证明。→ birth、→ environment hash。

**Machine run**（机器运行）— 诞生之后调用的一次执行：提交步骤、构建、指纹、过期行的执行、记日志、裁决、渲染。→ run number 只数改变了事实的运行（构建跑过或行执行过）；一次只测量并渲染的运行什么也不改变。

**Marker (not-a-requirement)**（标注，not-a-requirement）— 登记簿的驳回：被声明为不提出任何需求的愿望行，其自身的话被逐字引用在一旁，附一个原因。引文必须与愿望自己的文本精确一致——驳回一个需求就要求把它抄进签名的语料；这一标记无法悄无声息。例：标题行标注为 `quote: "a counter", reason: the wish's title names the work, it
demands nothing`。

**Merge**（合并）— 提交法则：行为按 id 合并（列出的头部整体替换——name、prose、scope、covers——行按 → run key 合并）；要求按 id 同法合并；标注清单与 artifacts 清单在提交携带时整体替换；`remove` 退役现存的 id；缺失的字段什么也不改变。经济性：提交的次数从不影响代价——未变的行不被重发。

**Next instruction**（下一条指令）— 机器唯一的祈使句，终端行与 `state.md` 的 `next:` 行同文：构建红说修构建；语料空说提交第一份文档；行红说读报告去修；行过期说再运行一次；裁决立于当前语料版本说把 `state.md` 给人看；全绿说把 `corpus.yaml` 复制到 `inbox.yaml` 再运行以记录裁决。
机器可处的每个状态恰有一条指令——绝无两个真相。

**Note**（笔记）— 文档携带的自由文本（`notes: [{text: …}]`）。机器从不解读笔记：它存储文档的规范字节，渲染时把笔记与机械的 → tags 一并列出。它是给人的通道，不是进入机器的通道。

O

**Object store**（对象库）— `journal/objects/` 下的内容寻址存储：对象的名字是其字节的 sha256；其文件为 `<first two hex>/<remaining sixty-two>`。相同字节只存一次——由构造去重；每次写入都重读重验，每次读取都校验其摘要。愿望的字节、每份被接受文档的规范字节、每个合并后行为的规范字节都活在这里，不可变。→ digest。

**Orphan requirement**（孤儿要求）— 没有任何现存行为在其 covers 中命名的现存要求。挡住裁决（`not yet — the requirements …
stand uncovered by any behavior's covers`）。→ covers。

P

**Pins**（固定）— 区的可选环境声明：`env` 文件，一行一个 `KEY=VALUE`，键 `[A-Za-z_][A-Za-z0-9_]*`，无 `export`、无引号、无绝对路径（固定随树而行）。注释与空行放行，末尾回车被容忍。任何其他形状的行都是一次响亮的拒绝，点名文件、该行与法则。同名时固定胜过干净基底。例：`TOOLS=tools/bin`——值可以是相对路径，绝不能是绝对路径。

**Process group**（进程组）— 启动纪律：机器的每条命令运行在自己的组里，它留下的任何活物（服务器、工作进程、shell 拉起的东西）随组同死——向组与进程发 kill 信号，再有界等待真正死亡。一行的残留绝不比行活得久。

**Proof**（证明）— 绿行的指纹：对该行规范字节、其行为的 → scope fingerprint 与 → environment hash 的 sha256。所录证明等于当前证明期间，该行被 → kept green；三者任何一个移动都使它 → stale。类比：盖在行、其输入与其环境之上的一枚蜡封——破其一，封即破。

**Prose**（prose）— 行为在作者笔下的自我描述：用户得到什么、为什么。必填且非空；原样搬上行为的 spec 页。机器只查有无，从不查好坏——阅读是人的事。

R

**Red**（红）— 一种行状态：它跑过且至少一个期望破损（破损事实，按测得原样记入日志，即原因）。红行在报告中按原因分组。跳过法则不分颜色：现存的红恰在 → proof 移动时——即其输入变化时——重跑，与让绿行保持绿的是同一条法则；但现存的红永远冒充不了完成，因为 → verdict 读的是事实的状态，绝不只读证明。现存裁决之下的红是 → drift。

**Red build freeze**（红构建冻结）— 失败的构建停下一切的法则：那次运行没有行执行，没有行事实移动；运行的记录只携带构建的事实，下一条指令说 `build red`。

**Refusal**（拒绝）— 机器对破损提交的回答：每条破损规则一行——确切的字段、→ law ids、测得的事实。提交的字节什么也不写；拒绝本身作为机器自己的事实记入日志并在 `state.md` 上计数；文档留在 `inbox.yaml`，作者修好被点名的位置再运行。例：`behaviors[0].rows[1].expect: the expect is empty —
name rc, out or files (law:document)`。→ validation。

**Registry**（登记簿）— 语料对愿望的账目：要求（各含其愿望行跨度）、标注与声明的 artifacts。按提交法则合并；整体摘要进裁决的 → registry digest。→ brief map。

**Registry digest**（登记簿摘要）— 对要求与标注合计规范字节的 sha256——愿望的全部账目封进一枚摘要，由裁决记录携带。

**Report**（报告）— `report.md`：最近一次改变事实的事件的全貌——对一次运行：构建的行、绿行计数、按破损原因分组的每个红行，外加完成动作说话时裁决的说明；对一次拒绝：每条拒绝一行外加修复指针。移动时整体重写；一次什么也没改、什么也没闭合的运行让上一份报告原样站着。→ refusal、→ verdict、→ views。

**Requirement**（要求）— 愿望提出的一个需求：一个 id（`R` 加字母、数字与点——尾可空，如 `R1`）与它占据的愿望行（W 范围）。按 id 合并；只能经显式 `remove` 退役，且该 remove 同时清掉它的每一处覆盖。每行都落在某个要求的跨度或某个标注之内，愿望才算整体入账。

**Row**（行）— 行为内的一个可执行检查：一条命令（`run`——shell 行或 argv 列表）及其 → expect。命令的规范字节是该行的 → run key，也是其 → proof 的一部分；行在行为中的位置是其日志键（`<behavior id>/<index>`）。行为所证明的一切就是行。

**Run key**（run 键）— 命令的规范字节，行的合并键：提交来的现存 run 原地替换整行；新 run 追加；未列出的行保持。重新拼写的命令是一个新 run——原有那个继续成立。例：`./tool src out` 与 `["./tool", "src", "out"]` 是同一个 run 的两种拼写。

**Run number**（运行编号）— 改变事实运行的计数器。终端行的 `run <N>`，报告、状态、知识、spec 的页头都点名同一个数。拒绝不耗运行编号——它由自己的计数器计。

S

**Scope**（scope）— 行为声明的依赖：相对根的通配，命名行为立足的文件。被覆盖文件的摘要构成 → scope fingerprint；scope 内的变化使行为的行过期。不被任何 scope 覆盖的文件是 → uncovered sources 或声明的 artifacts。有行而无 scope 的行为每次运行都重跑——永远给行一个 scope。

**Scope fingerprint**（scope 指纹）— 对该行为排序后的 `(path, file-digest)` 对的摘要——其 scope 映射的内容。不存在的 scope 文件拼写为 `absent`：映射点名必须成立之物，指纹看见实际成立之物。

**Scope glob**（scope 通配）— scope 的拼写：一种相对根的斜杠模式，各段可含 `[A-Za-z0-9-._*?[]`；`**` 段吞下零个或多个目录，`*`/`?`/`[...]` 在一个段内匹配。例：`src/**` 覆盖 `src/` 之下的一切（含 `src/` 本身）；`*.md` 覆盖根处的 markdown。

**Signature (the verdict's)**（裁决的签名）— 对语料规范字节加按 id 排序逐个行为的 `\0 id \0
scope fingerprint` 的 sha256：被宣告的规格与宣告时的精确树状态，收进一枚摘要。状态页与裁决历史中显示短式（12 字符）。

**Spec tree**（spec 树）— 视图目录 `spec/`：`index.md` 加每个活行为一小页（id 与名字、运行编号、prose 原文照录、scope，以及逐行的命令、期望与带短摘要的证明现状）。退役行为的页面被删除——这棵树是现状语料的映像，别无其他。

**Stale**（过期）— 一种行状态：其 → proof 动了（其字节、其行为的 scope 文件、或环境）——或它从未跑过——或其行为未声明 scope。过期的行在下一次运行执行；指令数它们（`N row(s) stale — run again to execute
them`）。

**Standing**（现状）— 由 → fold 从日志重建的现在：目标、语料版本与构建、登记簿、行为及其顺序、行事实、运行编号、裁决、各次提交、拒绝与完成计数、教训。机器决定一切皆凭现状——而现状永远可以只从记录派生。

**State page**（状态页）— `state.md`：一页之上的现状——目标与愿望的地址、带每个标注与未覆盖行的概要映射、语料版本、三个计数器、诞生时的机器版本、带 scopes-moved 标记与历史的裁决、每个行为一行、声明的 artifacts 与未覆盖源文件、知识计数、以及 `next:`——与终端行同文。→ standing、→ views。

**Submissions**（提交）— 被接受的文档，在 `state.md` 上与被拒的、完成的并列计数——三套独立的账：槽收下的文档、它拒绝的提交、完成了工作的完成动作。

T

**Tags**（标签）— 笔记的机械分组：笔记自身的词与实例 → vocabulary（愿望的词与现状语料的词——ASCII 字母数字的小写连串，两个字符及以上）的交集。每条笔记的标签随行携带；索引把每个标签映射到其笔记编号。只作分组——绝不是检查；任何地方都没有语义。

**Template**（模板）— `template.yaml`，诞生时由正典生成：带教学注释的文档形状。复制、编辑、作为 `inbox.yaml` 提交。解码通过却违反规则的文档仍被拒绝——模板教形状，校验守法则。

**Terminal line**（终端行）— 成功运行时调用的一行输出：`punchtape: run <N> — <instruction>`。指令点名要触碰的文件，与 `state.md` 的 `next:` 行同文。例外：首次接触打印整份契约；尚无实例的状态打印它那一条指令行；无法发生的调用改用它单独的错误行作答——退出码 1。机器要说的其余一切都在区的文件里。

**Torn tail**（撕裂尾部）— 写入中途被截断的日志记录（崩溃、断电）。它不会弄瞎机器：完好记录照常加载，撕裂字节隔离进旁路文件（`<epoch>.torn`），纪元文件从其完好记录逐字节重建。末位之外解析不过的块是人为损坏——一个诚实的错误。→ epoch。

**Tree walk**（树遍历）— 机器看工作树的唯一方式：一次有序遍历，跳过工作根处的区（`.punchtape`）与任何位置上按名匹配的版本管理簿记目录（`.git`、`.hg`、`.svn`），收集相对根的文件路径。遍历喂养 scope 指纹与未覆盖文件划分。机器从不把树的内容当代码读——只当作待摘要的字节与待运行的命令。

U

**Uncovered sources**（未覆盖源文件）— 没有行为 scope 覆盖、也没有 artifact 通配声明的树文件（AGENTS 块自己的文件除外）。在 `state.md` 上一行一个点名；一个未覆盖源文件就挡住裁决（`not yet — the sources … stand uncovered`）。机器的缺口是可见的事实：用 scope 覆盖它们，或声明它们。

V

**Validation**（校验）— 文档被接受之前通过的全部规则集：id 字母表与唯一性、对照愿望宇宙的 W 范围语法、标注原因与逐字引文、合法通配与相对根路径、命名现存要求的 covers、携带期望的行、命名现存 id 的 remove——外加对未列出而幸存行为的悬空 covers 检查。每次拒绝点名字段、事实与法则 id。→ refusal。

**Verdict**（裁决）— 机器对完成的宣告，只在 → completion act 时、且每道门禁成立时记录：语料非空；每个行在当前指纹下绿；愿望整体入账（每行都在某个要求跨度内或被标注）；无孤儿要求；无未覆盖源文件。记录携带编号、语料版本、→ signature、→ registry digest、每个行为的 scope 指针与收官运行编号；一条完成记录随之落地。只追加——新裁决从不改写旧裁决。差任何一点就是 `not yet` 加报告中每类空洞一行。

**Verdict history**（裁决历史）— 状态页的派生编年史：每条记录在案的裁决（运行、编号、版本、短签名）；每次 → drift（现存裁决下有红行的运行，带红键）；每次治愈（之后第一个无红行的运行）。日志没有携带的，历史就不说。

**Version flag**（版本标志）— `punchtape --version`，恰好这个拼写且单独成行：打印 `punchtape <version>` 并在触碰任何状态之前以 0 退出——唯一给人的便利；契约从不提及它。→ the call、→ exit code。

**Views**（视图）— 区的生成文件：`state.md`、`report.md`、`knowledge.md`、spec 树、`corpus.yaml`。日志的映像——内容变化时整体重写，不变化时绝不触碰；落不了地的视图是一次响亮的失败（过期的脸就是谎言）。

**Vocabulary**（词汇表）— 实例自己的词集：愿望字节的每个词与现状语料规范字节的每个词——ASCII 字母与数字的小写连串，两个字符及以上。笔记的 → tags 是其词与该集合的机械交集；任何地方都没有语义——实例从未携带过的词，什么也回答不了。

W

**W range**（W 范围）— 愿望行的唯一拼写：`W<n>` 或升序的 `W<a>..W<b>`，逗号相连（`W1..W4, W9`）。编号按文件顺序命名愿望的非空行，诞生时定死永不再变；要求的 brief 跨度与标注的行都乘着这套语法，机器也用它把编号集拼写回去，连续段折叠（`W19, W23..W25`）。→ wish、→ requirement、→ marker。

**Wish**（愿望）— 人的所愿，一字不差，诞生前放进 `wish.md`。诞生把它永远定为 → goal，并按文件顺序把它的非空行编号为 W1…Wm——编号永不变，每个要求跨度与标注都引用它们。愿望的大小决定语料的大小——不是品味。

**Wish coverage**（愿望覆盖）— 愿望宇宙上的算术：哪些行被某个要求的跨度或某个标注的跨度认领，哪些作为 → holes 站着。同一个函数喂养状态页的概要映射与裁决的愿望门禁——绝无两个真相。

**Wish slot**（愿望槽）— `wish.md`，诞生前的输入文件。有它而无日志——下一次运行诞生实例并消费该槽；无它——机器回答它那一条指令行，不创建任何东西。槽在诞生之后即死：目标已定死，除它之外没有任何东西能创建实例。

**Working root / working tree**（工作根 / 工作树）— 携带区（调用在其起始点处或上方找到它）与其旁一切的目录。树是代理的领地：机器遍历它、摘要它、在其中运行命令——且从不把它的内容当代码读。

Z

**Zone**（区）— `.punchtape/`，机器拥有的唯一目录：槽（`wish.md`、`inbox.yaml`、`env`）、生成的现状文件（`corpus.yaml`、`state.md`、`report.md`、`knowledge.md`、`spec/`）、带对象的日志、以及机器自己的 `cache/` 与 `tmp/`。绝不手工编辑；区外立着一条记录——工作根中的 → AGENTS block。
