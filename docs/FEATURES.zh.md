你只管跟你的 AI 助手说话——而 **punchtape 驱使 agent。**从任务
诞生那一刻起，第二方接过方向盘：一个永不睡觉、永不遗忘、对工人
的话一个不信的工头。它在每一回合把下一步交给 agent，用真实运行
来度量每一个声称，并且拒绝让工作在真正完成之前结束——从起点到
封存的完成，卖萌、疲劳或「相信我」都不是出口。你不再是自己 AI
的质量部门。

功能按分量排序：先是改变一切的功能，其后是得力助手，最后是小而
美的细节。数字是项目实地研究中的实测事实，标注诚实；其余一切都是
已交付机器的实际行为。

## 改变一切的功能

### 你从不操作它——你只管继续跟 agent 说话

没有什么要学，因为没有一个部件需要你来操作。往你的助手里贴一句
话，仅此一次——从此你的提示就是全部接口：你用平常话写下想要
什么，其余交给 agent，机器也在其内。机器还会在你项目的指令文件里
留一段简短笔记，于是每个新的 agent 会话无需你说一个字就能发现
它。**零新习惯，零新命令：机器像电一样入户——你从不操作它，只管
用插座里出来的东西。**

### 机器驱使 agent——从第一行到封存的完成

放任不管，AI 会给自己的作业打分：写完、宣布成功、继续前进。
punchtape 把角色倒转——**AI 成为工人，机器成为工头，而工头掌管
工地。**在每一个节点，机器发出的下一步永远只有一条（一行字：现在
做什么、动哪个文件）；一切工作从同一扇门进来；每个声称都以运行来
度量，而非询问；潦草的文书被退回，并点名确切之处。而循环——下一
步、工作、检查、下一步——不会因为工人说了句好了就结束：机器一直
驱使到工作真正做完，然后亲自封存完成。你得到两个职责分明的角色：
一个聪明但偶尔潦草的工人，和一个不留情面、不知疲倦的检查员。
**你唯一需要拉的操纵杆，就是你的提示。**

### 检查从你身上卸下——机械地，每一次

助手永远说「做完了」；查明真假一直是你晚上的事——每个任务、每次
编辑、永远。现在，AI 在你的任务文本旁边写下每一部分如何检查（真实
命令、预期结果），机器则亲自在你的真实项目里执行这些命令，每一次
都执行。它从不问 AI 工作行不行——它度量。**从你的任务到记录在案
的完成，必须由你留意的节点为零：写下它，走开，回来收结果。**

### 「done」可证明地意味着你的整个任务——逐行

你要十样东西，交付里出现七样，缺的三样由你的客户发现。这里不会：
你的原始任务文本被原样保存——永远——它的每一行都必须有交代。
要么一条检查证明它完成，要么它被公开划掉，附上它自己的原文引用
和旁边的理由。有哪行没有交代？不记录完成——机器确切点名缺什么。
跳过一项要求仍然可能，但只能大声地、书面地、在 AI 自己的报告里。
一切通过时，完成被一枚数字印章封存：哪些检查、对着你代码的哪个
版本。**一个「done」，你可以把它交给老板、客户，或六个月后的
自己。**

### 一份规格——任意实现，外加免费的可读手册

规格通常以三种方式腐烂：随聊天会话死掉、随技术栈死掉、文档与已
建成之物漂移。在这里，AI 交上的一切都落成一份机器可读的规格——
每个功能带作者原话的描述、它立足的文件、证明它的检查——而这一个
文档向两个方向编译。编成代码：规格固定的是可观察行为，而非实现
（机器在机械上被禁止认识任何语言或框架），所以任何技术栈里的任何
AI 都能构建它——明年用另一种语言重写产品，同一批检查以同样方式
验证它，绿色的结果随规格同行，作为它的证明。编成文字：机器自己为
每个功能渲染一页——逐字描述、检查、当前状态——外加整件工作的
一页状态，每次运行重新生成，从不手写，从不陈旧。**规格是源头；
代码是它的一种翻译；可读手册是另一种——而手册是免费的。**

### 经济账是测过的——省下的是你的小时

每个工具都承诺节省；这一个出示收据。三代实地研究——真实任务、
两个阵营（用机器与不用机器）、盲评裁判——每次度量的都是同一个
科目：验证工作，从前归你的那一部分。不用机器，每一个任务都需要
一次人工式验收；走机器则只在例外时触发——第一代 40 个单元中
7 次，最后一代是**25 个任务 2 次，对照不用机器的 32 次**。检查
科目收缩了 **×60**，随后 **token ×17.6 / 时间 ×9.2**，再随后
**×24.0 / ×5.5**——这是唯一在任何波次、任务或技术栈中都不变号
的成本。按要紧的货币计（真人验收工作的带标注估算）：**不用机器，
25 个任务吃掉你 4.4–7.3 小时的注意力——用机器 0.8–1.3 小时，
只算真实例外则实际 0.2–0.5 小时：每 25 个任务还给你 3.6–6.0
小时。**不用机器时，一个任务的全成本高出 **5×–19×**（实测，按
各次运行记录的价格）。完成来得快——五波系列测试中**每个机器任务
都在第一次尝试即获验收（25/25）**，最后一个系列**全部 50 个单元
封存**——而循环的喂养依旧便宜（**走机器 prompt-cache 命中率
99%，不用机器 58%**；机器自身的工作：每任务 0.5–37.8 秒）。质量
没有为这一切付出代价：盲评裁判在两个阵营的 **1720 项检查中发现
0 项缺失**。**token 价格年年下跌；你的小时不会。机器大手笔花廉价
资源，省的是昂贵的那一个——你的时间。**

### 同样的输入永远给出同样的答案

没有心情，没有平台，没有钟表时间：同样的任务文本、同样的代码、
同样的条件——同样的答案，在你的笔记本上、在服务器上、在明年。
记录不载时间戳；每一次写入都是原子的；在机器之间复制的历史文件
字节相同。如果机器写到一半死掉，下一次运行修复文件并保留每一条
完好记录——而且谁也不能编辑过去，AI 不能，你也不能（哪怕出于
意外）：历史只会增长。**不会衰变的事实：三月里绿色的结果，到
十月还是同一个意思。**

### 完整的记忆——跨会话、跨模型、跨月份

决定、修复、历史——这一切过去都活在一个终会被关闭和遗忘的聊天
里，于是每个新会话都把同样的东西再弄坏一遍。现在每一步都写进你
项目内的文件，写成事后无法编辑的形式：要了什么、交了什么、什么
失败了、怎么修好的。机器还自己保存教训——什么坏了、是哪一处
确切的改动修好的——度量而来，不是打字打来的。**换掉 AI 模型，
关掉会话，一年后回来：工头记得一切，工作从它停下的确切位置
继续。**

### 改动是便宜的——而且自动复查

交付之后，每次编辑过去都是一场赌博，因为没有人手工复查全部。
机器记得每条检查当时对着什么运行——哪些文件、哪些条件——于是
你改一个文件时，它只重跑依赖该文件的检查，其他一概不动。第一次
全量检查是慢的那次；其后每次检查只花几秒。**编辑不再吓人——于是
编辑终于发生——而机器每次都替你量好爆炸半径。**

### 完成之后坏了——你会知道

上个月的「done」随着代码持续变动，悄悄变成谎言。这里悄悄不了：
完成封存之后，任何后来的破坏性改动都会在你下一次查看时现身——
哪次改动弄坏了它、又是何时再修好的。没有监视器，没有后台密探：
机器每次运行都把封存之物与现存之物比对。**旧的承诺不会在沉默中
腐烂——要么它仍然工作，要么机器点名它停下的那一刻。**

### 它完全运行在你的机器上——无云、无账户、无遥测

回传总部、索要账户或悄悄上传你代码的开发工具，会把你的项目变成
别人的事。这一个只与本地文件和本地命令打交道的单个小程序——
它的代码里完全没有网络调用。无登录、无密钥、无使用报告；它甚至
不把你的代码当作代码来读，它只运行你的命令、比较字节。**一位
可以在上锁地下室的笔记本上运行的检查员——离线、断网、对着机密
代码，因为没有任何东西有处可发。**

## 得力助手

### 配合你建的一切

机器对编程语言、框架或技术栈一无所知——这是设计使然，并在构建时
机械强制：任何技术的一个词都不得出现在它的代码里。只要你的项目
能用一条命令构建和运行，机器就能验证它——没有规定结构，没有框架
税。**项目是什么形状，仍旧是你自己的事。**

### 失败以维修手册到来，而非谜语

检查失败时，你同时看到两面——期望的是什么、实际发生了什么
（"expected the program to end cleanly, got error 1"；期望文本
"ok"，得到 "okk"）——相同的失败归入同一个清单，缺失的工具也有
通俗的解释：机器在哪儿找过、有哪三种修法。agent 读完通常一遍修完
一切。**最后的调试者不是你——失败报告才是。**

### 它拒绝测试坏掉的构建

如果你的项目有构建步骤，它最先运行。它失败或挂起，这一轮其余
什么都不跑，机器说：先修构建。**一次一个清楚的问题——而且在
破碎的地基之上不会有假的「全部通过」。**

### 卡死的命令劫持不了你的项目

每条命令都有硬性的 300 秒上限：挂起即被杀掉并连同原因记录为一次
失败，绝不卡死整轮运行。命令留下的任何东西——服务器、监视器、
游离的 worker——都随它一并清理。**你再也不会回到一个被遗忘的
后台进程搞瘫的项目。**

### 你始终看得见什么没有被检查

任何没有被检查盯着的文件，都在状态页上按名列出；你要么覆盖它，
要么公开接受这个缺口，而无人盯防的文件会挡住最终完成。**没有
看不见的盲区：查了什么写下来，没查什么也写下来。**

### 条件写在纸上——「我机器上能跑」已死

每条检查都在完全相同的白纸黑字条件下运行——同样的路径、同样的
设置，外加你在项目内一次性固定下来、随代码同行的一切。条件一旦
改变，机器会察觉并重新检查，而不是给你看一张陈旧的「通过」贴纸。
**绿色的结果是关于已知条件的事实——而环境漂移从机器那里传到
你，而不是从客户那里。**

### 文书里的错误直指确切位置

AI 的报告文件有错时，机器点名确切位置和错处，每个错误一行；文件
原地不动——修好被点名之处再运行，毫无损失。文件格式里藏着的
任何鬼祟之物，在被读取之前、在任何状态被触碰之前，就被干脆拒绝。
**一遍修好，不是三遍——而这条输入通道无聊得没人想攻。**

### 小改动只花小消息

你只发送变了的部分；未提及的一切保持原样；重新排版不算数，因为
机器读的是文字所说的，不是它的排布。**十处小修改花十条小消息
——绝不是十次规格全量重写。**

### 机器管住自己

谁来守卫守卫者？每次构建机器，它自带的示例任务必须通过真实的
机器——完整一圈，从任务文本到封存的完成——否则构建失败；同一次
构建还强制机器代码的每一行都被它自己的测试实际执行。**检查你
工作的东西，自己也在每次构建中被机械地检查。**

## 小而美的细节

### 它会解释自己——用三种语言

在空文件夹里运行它，它打印完整手册，包括 AI 所写文件的确切形状，
并创建一份可填写的模板。英语、俄语、中文。**是说明找到 agent，
不是 agent 去找说明。**

### 你读到的页面永远为真

状态页和各报告每次运行都从记录重建——从不手改，从不陈旧——而
如果某一页写不出来，机器会拉响警报，而不是悄悄给你看旧的一页。
「下一步做什么」那一行在终端里和页面上永远一致。**凡在磁盘上的，
都是当前的。**

### 给你的脚本一个诚实的 yes/no

机器说成了（exit 0），就是成了——在工作内部发现的问题是数据，
不是崩溃。它说调用没有发生（exit 1），就是没发生。**把它包进
任何脚本，然后相信答案。**

### 一个词就是全部接口——对 agent 而言

没有旗标，没有菜单，没有模式：agent 运行一个词，拿回一行——
下一个动作，指向要动的文件。这也是为什么幻觉出一个旗标的模型
无法误用机器：**根本没有旗标可幻觉。**

### 完成手势笨得漂亮

AI 如何正式地说「完成了」？它把机器自己的「什么应当为真」清单
原样复制并交回——把清单原样发回，这个动作本身就是签名。**没有
什么要发明，没有什么要排版，最后一英里没有什么能弄错。**

### 无守护进程、无监视器、运行间隙零足迹

机器只存在于它运行的那一刻：没有后台进程，没有吃内存的服务，
没有任何东西盯着你的文件——变更检测是运行时的算术，不是常驻
密探。**两次运行之间，你的机器甚至不知道它在那里。**

### 真相是一个文件夹

一切——任务、AI 交上的每份报告、每次运行的结果、每一次完成——
都以普通文件的形式活在你项目内的一个隐藏文件夹里。把它复制到
另一台机器，状态字节相同；备份它，diff 它，放进版本控制。**没有
数据库，没有导出，没有迁移。**

### 一行装好——而且免费

往你的 agent 贴一句话：它取回为你平台备好的二进制（Linux 与
macOS，x64 与 ARM，校验和已公布）或从源码构建，并放进你的
PATH——免费、MIT 许可、无账户、无付费墙。**一个会话之内，从零
到第一次封存的完成。**
