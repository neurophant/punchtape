你只管跟你的 AI 助手说话——而 **punchtape 驱使 agent。**从任务
诞生那一刻起，第二方接过方向盘：一个永不睡觉、永不遗忘、对工人
的话一个不信的工头。它在每一回合把下一步交给 agent，用真实运行
来度量每一个声称，并且拒绝让工作在真正完成之前结束——从起点到
封存的完成，卖萌、疲劳或「相信我」都不是出口。你不再是自己 AI
的质量部门。

功能按分量排序：先是改变一切的功能，其后是得力助手，最后是小而
美的细节。数字是项目实地研究中的实测事实，标注诚实；其余一切都是
已交付机器的实际行为。

## 改变一切的功能

### 你从不操作它——你只管继续跟 agent 说话

没有什么要学，因为没有一个部件需要你来操作。往你的助手里贴一句
话，仅此一次——从此你的提示就是全部接口：你用平常话写下想要
什么，其余交给 agent，机器也在其内。机器还会在你项目的
`AGENTS.md` 里留一段简短笔记，于是每个新的 agent 会话无需你说
一个字就能发现它。**零新习惯，零新命令：机器像电一样入户——你
从不操作它，只管用插座里出来的东西。**

### 机器驱使 agent——从第一行到封存的完成

没人管的 AI 会给自己的作业打分：写完、宣布成功、继续前进。
punchtape 把角色倒过来——**AI 成为工人，机器成为工头，而工头
管着工地。**在每一个点上，机器精确地发出唯一的下一步（一行：
现在做什么、动哪个文件）；所有工作从一扇门进来；每一个声称都以
运行来度量，而不是靠问；潦草的文书被原路退回并点名确切位置。
而循环——下一步、干活、检查、下一步——不会因为工人一句话就
结束：机器一直驱动到工作真正做完，然后亲自封存完成。你得到分工
干净的两方：一个聪明但偶尔潦草的工人，和一个不留情面、不知疲倦
的检验员。**你的提示是你永远唯一需要拉的操纵杆。**

### 检查从你身上卸下——机械地，每一次

助手永远说「做完了」；查明真假曾是你的晚间功课——每个任务、每
次改动，永远如此。现在，AI 在代码旁边写下每一部分如何被检查
（真实命令，加上它们必须打印的精确字节），机器亲自执行这些
命令——就在你真实的项目里，每逢它们过期就执行。它从不问 AI
工作能不能用——它测量。**在你的任务与记录在案的完成之间，你
的注意力零个必经点：写下，走开，回来收结果。**

### 「done」可证明地意味着你的整个任务——逐行

你要十样东西，交付只有七样，缺的三样由你的客户发现。这里不会：
你的言语存放在机器自己持有的文件里并编号——每个非空行，从 D1
到 Dn——每一行在到来之时都必须得到申报的结果：工作、回答、
执行、描述、一条「非要求」的标记，或一个提给你的开放问题。开放
问题会扣住完成，直到你用自己的言语回答；驳回必须响亮、成文、
带理由。在另一侧，你项目的每一行都必须要么被某条检查的 claim
声明，要么被公开划掉并附上引用你的言语或机器法则的理由。有什么
未分解、未声明、未回答？没有完成——机器精确说出缺什么。全部
通过时，完成以数字签名封存：哪些检查、在哪个版本的语料上。
**一份半年后可以递给老板、客户或你自己的「done」。**

### 一份规格——任意实现，外加免费的可读手册

规格通常死于三条路：随聊天会话而死，随技术栈而死，随文档与实建
漂移而死。这里，AI 交上来的一切都落成机器持有的一份语料——每个
行为带着作者亲笔的描述、它所立足的精确代码行、证明它的 rows
——而这一份文档向两个方向编译。编成检查：rows 钉住可观察的
行为（一条命令和它的精确字节），而非实现——机器被机械地禁止
认识任何语言或框架——因此任何 AI 在任何栈里都能重新挣得同样的
证明；明年把产品换语言重写，同样的 rows 照样验证它，claims
重新画到新文件上。编成散文：机器自己为每个行为渲染一页——描述
原样、所 claim 的行及其摘要、命令与期望、当前状态——外加整份
工作的单页状态，每次运行重新生成，从不手写，从不 stale。
**规格是源头；代码是它的一种翻译；可读手册是另一种——而手册
是免费的。**

### 经济账是测过的——省下的是你的小时

每个工具都许诺省钱；这个拿出收据。三代实地研究——真实任务、
两个阵营（带机器与不带）、盲评裁判——每次度量同一笔账：验收
工作，也就是从前属于你的那部分。没有机器时，每个任务都需要一次
人工式验收；经过机器，它只在例外时触发——第一代 40 格中的
7 格，最后一代是 **25 个任务里 2 次，对不带它的 32 次**。验收
这笔账收缩了 **×60**，然后是 **×17.6 tokens / ×9.2 时间**，
再然后 **×24.0 / ×5.5**——唯一在任何浪潮、任务或栈中都不变号
的成本。换成要紧的货币（为验收工作的真人做的、标注过的估算）：
**25 个任务在不带机器时吃掉你 4.4–7.3 小时的注意力——带上
它 0.8–1.3 小时，只算真正例外时约 0.2–0.5 小时：每 25 个任务
还给你 3.6–6.0 小时。**不带它，一个任务的全口径成本高
**5×–19×**（实测，按各次运行记录的价格）。完成来得快——五浪
电池里**每个机器任务都首次尝试即被接受（25/25）**，最后一个
系列**全部 50 格封存**——而循环喂起来依然便宜（**经机器的
prompt 缓存命中率 99%，不带它 58%**；机器自身的工作：每任务
0.5–37.8 秒）。质量没有为这一切付账：盲评裁判在两个阵营的
**1720 项检查中发现 0 项缺失**。**token 的价格逐年下降；你的
小时不会。机器大方地花便宜的资源，省下贵的——你的时间。**

### 同样的输入永远给出同样的答案

没有情绪，没有平台差，没有时钟：同样的任务文本、同样的代码、
同样的条件——同样的答案，在你的笔记本上、在服务器上、在明年。
记录不携带时间戳；每次写入都是原子的；在机器之间复制的历程文件
字节相同。机器若在写入中途死去，下一次运行把撕裂的尾部隔离、
保留每条完好记录——而任何人——AI 也好、无意中的你也罢——都
改不了过去：历史只增不减，你的言语被碰的过往行会让机器停下。
**不会腐烂的事实：三月里绿的结果，在十月里含义相同。**

### 完整的记忆——跨会话、跨模型、跨月份

决定、修复、历史——这一切曾住在被关掉就遗忘的聊天里，于是每个
新会话重新弄坏同样的东西。现在每一步都写进你项目里的文件，写成
事后改不动的形式：要了什么、交了什么、什么坏了、怎么修的。机器
还自己保存教训——每一条它后来看到转绿的 red row，带着该 row
前后与两次运行号——测出来的，不是打出来的：任何模型的 token
消耗为零。**换掉 AI 模型、关掉会话、一年后回来：工头记得一切，
工作从停下的那一格继续。**

### 改动是便宜的——而且自动复查

交付之后，每次编辑都曾是赌局，因为没人手工复查一切。机器记得
每条检查当时对着什么运行——它自己的字节、它行为精确 claim 的
行、以及整个环境——于是你改一个文件，它只重跑 claim 了该文件
各行的检查，别的都不碰。第一次全量检查是慢的那次；其后每次只花
几秒。**编辑不再吓人——于是编辑终于发生——而机器每次都替你
量出影响半径。**

### 完成之后坏了——你会知道

上个月的「done」随着代码继续移动而悄悄变成谎言。这里不会悄悄：
完成封存之后，任何后来弄坏被 claim 之行的改动，下次你一看就会
现身——抓到漂移的 run 与重新转绿的 run 都写进裁决历史，而站立
的裁决本身就写着「open (drift since run N)」，直到一次提交重新
挣得它。没有监视器，没有后台密探：机器在每次运行时把封存的与
当前站立的做对比。**旧的承诺不会在沉默中腐烂——要么它还能用，
要么机器说出它停摆的时刻。**

### 它完全运行在你的机器上——无云、无账户、无遥测

打电话回家、索要账户、悄悄上载你代码的开发工具，把你的项目变成
别人的事。这一台是只与本地文件和本地命令打交道的一个小程序——
它的代码里没有任何网络调用。无登录、无密钥、无使用报告；它甚至
不把你的代码当代码读——它只运行你的命令、比较字节。**一个可以
在锁着的地下室笔记本上跑的检验员——离线、离网、对着机密代码，
因为根本没有地方可以发送任何东西。**

## 得力助手

### 配合你建的一切

机器对编程语言、框架、技术栈一无所知——这是设计，且在构建时被
机械强制：任何技术的一个词都不许出现在它的代码里，对机器自身
源码的扫描会在这个词落地的那一刻让构建失败。你的项目只要能被
一条命令构建并运行，机器就能验证它——没有规定的结构，没有框架
税。**你项目的形态仍是你自己的事。**

### 失败以维修手册到来，而非谜语

检查失败时，你看到两面——期望什么、实际发生什么（「exit: got
1, want 0」；期望精确字节 `ok\n`，得到 `okk\n`）——相同的失败
归入同一清单列在各自的原因之下，缺失的工具也有大白话解释：row
的环境就是运行机器的那个 shell 的 PATH 与 HOME 加上区的钉——
让命令可达、把它钉住、或用相对路径调用项目文件。agent 读完
通常一遍修完。**你不是最后关头的调试者——故障报告才是。**

### 它拒绝测试坏掉的构建

如果你的项目声明了构建命令，它先跑——每次启动、任何 row 之前。
构建失败或挂死，本轮其余一切不跑，机器说：先把构建修好。**一次
一个清楚的问题——绝无在坏地基上伪造的「全过」。**

### 卡死的命令劫持不了你的项目

每条命令都有硬期限：默认 300 秒，区可以用一行钉提高它
（`PUNCHTAPE_ROW_TIMEOUT` 以整秒计）。挂死被杀掉并作为带原因的
红色事实记录，绝不卡死运行。而命令留下的一切活物——服务器、
监视器、走失的 worker——随它的进程组一同死去。**你永远不会回
到一个被遗忘的后台进程弄砖的项目。**

### 你始终看得见什么没有被检查

项目里每一行没有被任何检查 claim、也没有被任何响亮豁免盖住的
代码，都按名字列出——逐文件、带行区间——在状态页上（前十个
文件），并有一份不封顶的完整空洞账本；你要么用 claim 盖住它，
要么公开接受这个洞，而未盖住的行拦住下一次完成。机器甚至用它
自己的空洞算术替你起草豁免清单——你补的是理由，不是路径。
**没有看不见的盲区：查了什么写在纸上，没查什么也写在纸上。**

### 条件写在纸上——「我机器上能跑」已死

每条检查都在一模一样、写在纸上的条件下运行：调用方 shell 的
PATH 与 HOME，加上项目自己的钉（`.punchtape/env`，一行一条
KEY=VALUE——只用相对路径，钉随树走）。机器自身的版本、主机与
实际传递的环境进入每份证据的指纹：其中任何一项移动，机器都会
察觉并复查，而不是给你看一张过期的「已通过」贴纸。**绿色的
结果是关于已知条件的事实——环境的漂移从机器那里到达你，而不
是从客户那里。**

### 文书里的错误直指确切位置

AI 的提交文件有错时，机器点名确切的字段、事实和被违反的法则，
一条错误一行；文件原地不动——修掉点名处再运行，什么都不会丢。
藏在文件格式里的一切花招——锚点、别名、标签、merge 键、重复
键、未知字段、缩进里的制表符——在门口就被拒绝，从不被解释：
装甲在模型看到之前就巡视完解析树。**一遍修好，而不是三遍——
而且一条无聊得没人想攻击的输入通道。**

### 小改动只花小消息

你只发送变化了的部分；一切未被提及的原样站立；重新排版不算数，
因为机器在解码之后比较规范字节——同一内容的两种写法就是同一
内容。rows 按命令合并：同一命令替换它的 row，新命令追加，未列
出的站立。**十个小修只花十条小消息——绝不是十次规格全文重写。**

### 安静的回答动不了树

你的言语会要不同的东西：有的订购工作，有的只是提问、或想要一个
回报的事实。机器认真对待这个区别——一份只回答、执行或描述的
提交，会为该次运行锁住树：前后各测一次摘要，动了的树是一条
入志事实，扣住裁决，直到字节复原或该改动被作为申报的工作提交。
agent 无法在回答问题的同时「顺手」重写你的项目还称之为完工。
**安静的意图让世界保持原样——否则就大声说出来。**

### 机器管住自己

谁来监督监督者？机器每次构建时，它自己内置的示例任务必须跑过
真机器——完整循环，从最初的言语到记录在案的裁决——否则构建
失败；同一次构建还强制机器的每一行代码都被它自己的测试实际执行，
并强制它印出的契约与它强制执行的规则是同一个集合。**检查你工作
的那个东西，自己也在每次构建时被机械地检查。**

## 小而美的细节

### 它会解释自己——并随身携带手册

在空文件夹里运行它，它打印自己完整的法则——一页：如何开始、
文件是什么、机器的八条法则。诞生随后把同一份契约写进区里，旁边
是带文档精确形状的模板和点名机器每一扇门的参考页——于是完整
手册就住在你的项目里，常在手边，区永远不会教一条它的机器已经
离开的法则。用户文档以英文、俄文、中文发行。**说明自己找上
agent，而不是反过来。**

### 你读到的页面永远为真

状态页和报告在每次运行时从记录重建——从不手改、从不 stale
——而页面写不进去时，机器会拉响警报而不是悄悄展示旧页。「下一步
做什么」那一行在终端与页面上永远相同。**在磁盘上的，就是最新的。**

### 给你的脚本一个诚实的 yes/no

机器说它干了活（exit 0）时，它就干了——在工作内部发现的问题是
数据，不是崩溃。它说调用没有发生（exit 1）时，就没有发生。
**把它包进任何脚本，并相信这个答案。**

### 一个词就是全部接口——对 agent 而言

没有旗标、没有菜单、没有模式：agent 运行一个词，拿回一行——
下一个动作，指向要动的文件。唯一的例外是 `--version`，一个
契约从不提及的、给人用的旗标。这也让产生旗标幻觉的模型无法
误用它：**没有可以幻觉的旗标。**

### 完成手势笨得漂亮

AI 如何正式地说「做完了」？往 inbox 里写一行——`done: true`，
再无其他。这行裸文就是签收；机器随后自己重新度量一切。**没有
要发明的东西，没有要排版的格式，最后一英里没有可弄错的东西。**

### 无守护进程、无监视器、运行间隙零足迹

机器只存在于它运行的那一刻：没有后台进程，没有吃内存的服务，
没有盯着你文件的东西——变更检测是运行时的算术，不是常驻密探，
而暂存目录在每次运行结束时被清空。**两次运行之间，你的机器甚至
不知道它在。**

### 真相是一个文件夹

一切——言语、每份被接受的提交、每次运行的结果、每个完成——
都住在你项目里一个隐藏文件夹内的普通文件里。把它复制到另一台
机器，状态字节相同；备份它、diff 它、放进版本控制。**没有
数据库，没有导出，没有迁移。**

### 一行装好——而且免费

往你的 agent 贴一句话：它会取回为你平台准备好的现成二进制
（Linux 与 macOS，x64 与 ARM，校验和已公布）或从源码构建，并
放到你的 path 上——免费、MIT 许可、无账户、无付费墙。**从零
到第一个封存的完成，一个会话之内。**

## 诚实的限制

机器测量字节与集合——从不测量含义。下面每一条都是已交付机器的
活生生事实，直说：

- **言语由 agent 的手进入。**机器从看不见你的聊天；它亲自从
  `demands.md` 取走你的言语并封锁过去，但它无法知道一句从未被
  写下来的话——而没带来新言语的提交会签署「没有新言语」：这份
  签名永远留在日志里，显示在状态页上。
- **绿色的裁决是形式完整，不是正确性。**每行已分解、每条 row
  带钉住的字节保持绿色、树等于 claims 加响亮豁免——机器读不出
  代码做的是不是你心里想的事；你沿 spec 页的那一眼就是审计，
  而那些页面正是为这一眼而建。
- **文档是 YAML，而 YAML 咬人。**含「: 」或逗号的值要加引号；
  多行钉保持一行；缩进里的制表符被拒绝。在最近一次实地演练中
  这是最常见的拒绝（56 次中的 24 次）——每一条都指名自己的
  位置，没有一条丢数据。
- **一个区、一台机器。**由另一个 punchtape 版本诞生的区会被
  拒绝——归档它，从头再来；没有迁移。
- **仅限 Linux 与 macOS**（amd64/arm64）；rows 经 unix shell
  运行，命令只看得见 PATH、HOME 和钉。
- **运行按区锁串行化。**同一时刻只有一遍运行持有区（`run.lock`，
  由内核释放，死亡安全）；并行调用排队等待——直到正在运行的这遍
  命令的期限。仅限本地文件系统：网络文件系统不作此承诺。
- **永远不要手改日志。**每条记录在读取时被核对；无法复原的，
  按名字拒绝。
