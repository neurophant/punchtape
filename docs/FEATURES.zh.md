# 功能
[English](FEATURES.md) · [Русский](FEATURES.ru.md) · **中文**

你跟你的 AI 助手说话——而 **punchtape 驱使 agent。**从任务诞生的
那一刻起，任务的真相由第二方持有：它在每个回合交给 agent 下一步，
用真实运行来测量每一个 claim，并且在工作真正完成之前拒绝让
它结束。你不再是自己的 AI 的质检部门。

功能按大小排列：先列最大的，再列支撑性的，最后是小便利。
数字是本项目实地研究的实测事实，如实标注；其余一切都是
已发布机器的实际行为。

下面你会遇到五个词，先用大白话说清。**区**是机器在你项目里
持有的 `.punchtape/` 文件夹。**row** 是一条检查：一条命令加上
它必须打印的精确输出。**proof** 是表明一条 row 依然成立的
指纹。**pin** 是一条 row 等待的精确字节。**corpus** 是行为
及其检查的常设集合。

## 最大的功能

### 机器由 agent 操作；你只写提示

没有什么可学，因为操作它本就不是你的事。把一句话贴给助手
一次——从此你的提示就是全部界面：你用平常的话写下想要的，
其余由 agent 完成，机器包括在内。机器还会在你项目的
`AGENTS.md` 里留一段短记，所以每个新的 agent 会话都无需你说
一个字就能发现它。你得到：零个新习惯、零条新命令。

### 机器驱动工作循环

放任自流时，AI 给自己的作业打分：写完、宣布成功、继续前进。
punchtape 把角色拆开：在每个点上机器只给出一个下一步（一行：
现在做什么、碰哪个文件）；所有工作从一扇门进来；每个 claim
靠运行来测量，不靠询问；潦草的文书被打回并点名确切位置。
循环以裁决结束，而不是执行者的话——你得到一个执行者和一个
检查者，各司其职。

### 检查不需要你

助手总说「做完了」；查证真假曾是你的夜晚：每个任务、每次
修改、永远如此。现在，AI 在代码旁边写下每部分如何检查（真实
的命令、必须打印的精确字节），机器亲自执行这些命令，就在你
的真实项目里，每次过期就重跑。它从不问 AI 工作行不行。它
测量。在你的任务和记录在案的完成之间，你的注意力没有一处
是必需的：写下、走开、回来看结果。

### 每句话被分解，每一行被 claim

你要十件东西，交付七件，缺的三件由你的客户发现。这里不会：
你的原话保存在机器自己持有并编号的文件里——每一非空行，
D1 到 Dn，每一行在到达时都必须得到申报的结果：工作、回答、
执行、描述、「非要求」的标记，或一个提给你的开放问题。开放
问题压住完成，直到你用自己的话回答；驳回必须响亮、成文、
附理由。另一侧，你项目的每一行要么被某条检查 claim，要么被
公开划掉并附引用你的言语或机器法则的理由。任何未分解、未
claim、未回答的东西 → 没有完成，机器会点名缺什么；全部通过
时，完成以签名封存——哪些检查、在你语料的哪个版本上——
一份可以拿给老板、客户或半年后的自己的「完成」。

### 一份 spec，任意实现——可读手册免费附送

specification 通常以三种方式腐烂：随聊天会话死去、随技术栈
死去、文档与所建之物漂移。在这里，AI 交来的一切落入一个由
机器持有的 corpus——每个行为带着作者原话的描述、它所站的
确切代码行、证明它的 rows——而这一份文档向两个方向编译。
编成检查：rows 钉住可观察的行为（一条命令和它的精确字节），
而非实现——机器被机械地禁止知道任何语言或框架——所以任何
栈上的任何 AI 都能重新挣得同样的证明；明年把产品换语言重写，
同样的 rows 照样验证它，claims 重画到新文件上。编成文字：
机器自己为每个行为渲染一页——描述逐字、claim 的行及其
digest、命令与期望、当前状态，外加整件工作的一页状态，每次
运行重新生成，从不手写、从不过期。spec 是源头；代码是它的
一种翻译；可读手册是另一种——而手册是免费的。

### 实测的经济学

每个工具都许诺省钱；这个给你看收据。三代实地研究——真实
任务、两个阵营（用与不用机器）、盲评裁判——每次测量同一项
支出：验证工作，原本属于你的那部分。不用机器时，每个任务
都需要一次人工式验收；通过机器，它只在例外时触发——第一代
40 个 cell 中 7 次，最后一代 **25 个任务中 2 次，对照不用
机器的 32 次**。验证这项支出缩减 **×60**，随后 **token ×17.6 /
时间 ×9.2**，再随后 **×24.0 / ×5.5**；在任何一波、任何任务、
任何栈中都不曾反转的唯一样目。以真正要紧的货币计（对真人验收
工作的明确估算）：**25 个任务不用机器要吃掉你 4.4–7.3 小时
的注意力——用机器 0.8–1.3 小时，只算真实例外则 0.2–0.5：
每 25 个任务归还 3.6–6.0 小时。**任务的全口径成本不用机器时
**高 5×–19×**（实测，按各 run 记录的价格）。完成来得快：
五波系列中**每个被验收的机器任务都一次通过（25/25）**，最后
一系列**全部 50 个 cell 封存**——而养这个循环很便宜（**机器侧
prompt 缓存命中率 99%，对照无机器的 58%**；机器自身的工作：
每任务 0.5–37.8 秒）。质量没有为任何一项买单：盲评裁判在
两个阵营的 **1720 项检查中找到 0 个缺失**。token 的价格逐年
下跌；你的小时不会。机器花廉价的资源，省昂贵的那一个。

### 确定性的运行

没有情绪、没有平台差异、没有钟表时间：同样的任务文本、同样
的代码、同样的条件，就有同样的答案，在笔记本上、在服务器上、
在明年。记录不携带时间戳；每次写入都是原子的；在机器之间
复制的历史文件逐字节相同。如果机器在写入中途死亡，下一次
运行把撕裂的尾部隔离起来，保住每一条完整记录——而且无论
谁、无论是 AI 还是不小心的你，都无法编辑过去：历史只增长，
你的言语被碰过的过往行会让机器当场停下。三月里绿色的结果，
在十月意味着同一件事。

### 历史在文件里——跨会话、跨模型、跨月份

决定、修复、来龙去脉，从前都活在一个会被关闭和遗忘的聊天
里，于是每个新会话重新弄坏同样的东西。现在每一步都写进你
项目内的文件，写成事后无法编辑的形式：要了什么、交了什么、
什么失败了、怎么修好。机器还自己保存教训——它后来看到变绿
的每条红 row，连同该 row 前后的字节和两个 run 的编号——
靠测量，不花任何模型的一个 token。换掉 AI 模型、关掉会话、
一年后回来：记录记得一切，工作从停下的地方继续。

### 增量式重跑

交付之后，每次修改都曾是赌局，因为没人手工重查一切。机器
记得每条检查是针对什么运行的——它自己的字节、其行为 claim
的确切行、以及整个环境——所以你改一个文件，它只重跑 claim
了该文件各行的检查，其余一概不碰。第一次全量检查是慢的；
之后每次检查只花几秒。每次改动的影响半径由机器替你量出。

### 完成之后的破坏会被抓住

上个月的「完成」随着代码继续移动而悄悄变成谎言。在这里不会
悄悄：完成封存之后，任何破坏 claim 行的后续改动都会在下次
查看时现身——抓住漂移的 run 和重回绿色的 run 都写进裁决
历史，站立的裁决本身显示 `open (drift since run N)`，直到一次
submission 把它重新挣回。没有监视器、没有后台间谍：机器在
每次运行时把封存的与站立的作比较。要么它仍然工作，要么机器
说出它停止的时刻。

### 离线、无账户、无遥测

悄悄回连、索要账户或偷传你代码的开发工具，会把你的项目
变成别人的东西。机器是一个只与本地文件和本地命令打交道的
二进制——它的代码里完全没有网络调用。没有登录、没有密钥、
没有使用报告；它甚至不把你的代码当代码读——它运行你的
命令、比较字节。它在锁着的地下室里的笔记本上运行，离线，
对着保密代码：无处可发。

## 支撑性功能

### 对技术栈不可知——由构建法则强制

机器对编程语言、框架、技术栈一无所知——这是设计，且在构建时
机械强制：任何技术的任何一个词都不许出现在它的代码里，对
机器自身源码的扫描会在这种词落地的瞬间让构建失败。只要你
的项目能被一条命令构建和运行，机器就能验证它——没有规定的
结构、没有框架税；项目的形态仍是你的事。

### 失败以字节给出 want 与 got

一条检查失败时，两边都摆在你面前——期望什么、实际发生什么
（`exit: got 1, want 0`；期望精确字节 `ok\n`，得到 `okk\n`）——
相同的失败按原因归成一组，缺失的工具被直白解释：row 的环境
是运行机器的 shell 的 PATH 和 HOME 加上区的 pin——让命令
可达、把它 pin 住、或用相对路径调用项目文件。agent 读了
通常一遍修完；你的调试器就是这份报告。

### 构建先行

如果你的项目声明了构建命令，它先跑——每次启动、在任何 row
之前。它失败或挂起，这一轮别的什么都不跑，机器说：先修构建。
一次一个清楚的问题——绝不在坏掉的地基上伪造「全部通过」。

### 命令的死线与进程组之死

每条命令都有硬死线：默认 300 秒，区可以用一行 pin 调高
（`PUNCHTAPE_ROW_TIMEOUT` 指定整秒）。挂起被杀掉并作为带
原因的红色事实记录，绝不卡死运行。命令留下的一切活物——
服务器、监视器、游离的 worker——随它的进程组一同死去；你
永远不会回到一个被遗忘的后台进程搞瘫的项目。

### 未覆盖的行被列出

没有被任何检查 claim、也没有被响亮豁免覆盖的每个项目行，
都被点名——按文件、带行范围——显示在状态页（前十个文件）
和一份不设上限的完整账本里；你用 claim 盖住它，或公开接受
缺口，而未覆盖的行挡住下一次完成。机器甚至从自己的洞算术
里替你起草豁免清单——你补的是理由，不是路径。查了的写
下来，没查的也写下来。

### 环境钉进每一个证明

每条检查都在完全相同的成文条件下运行：调用方 shell 的 PATH
和 HOME 加上项目自己的 pin（`.punchtape/env`，一行一个
KEY=VALUE——只有相对路径，pin 随树同行）。机器自身的版本、
主机和实际传入的环境都进入每个证明的指纹：其中任何一项移动，
机器就察觉并重查，而不是给你看一张过期的「通过」贴纸。绿色
的结果是关于已知条件的事实——环境的漂移由机器传到你这里，
而不是由客户。

### 拒绝点名确切位置

如果 AI 的 submission 文件有错，机器点名确切的字段、事实和
它违反的法则，一个错误一行；文件原地不动——修掉点名之处、
再跑一次，什么也不丢。藏在文件格式里的一切花招——锚点、
别名、标签、merge 键、重复键、未知字段、缩进中的制表符——
都在门口被拒，绝不被解释：在任何东西运行之前，机器亲自
走一遍文件的结构，把格式允许的每个花招都扔出去。一遍
修完，而且输入通道严格得容不下花招。

### 规范字节合并

你只发送变化的部分；未提及的一切原样站立；重新排版不算
数，因为机器在解码后比较规范字节——同一内容的两种写法是
同一内容。row 按命令合并：同一命令替换自己的 row，新命令
追加，未列出的站立。十个修补花十条小消息，绝不是十次 spec
全量重写。

### 安静的意图锁住树

你的话要求不同的东西：有的命令工作，有的只是提问或要一个
事实回报。机器认真对待这个差别——只回答、只执行或只描述的
submission 会为该 run 锁住树：摘要在前后各测一次，移动过的
树是一条入账事实，压住裁决，直到字节回来或该变更作为申报
的工作提交。agent 不能在回答问题时「顺手」重写你的项目然后
收工：安静的意图让世界保持原样——或者大声说明。

### 构建测试机器自己

谁来监督监督者？机器每次构建时，它自带的内置示例任务必须
穿过真实的机器——完整循环，从最初的言语到记录在案的裁决
——否则构建失败；同一次构建还强制机器代码的每一行都被它
自己的测试实际执行，并且它打印的契约与它强制的规则是同一
集合。检查你工作的那个东西，自己在每次构建时被机械地检查。

## 小便利

### 手册随区附带

在空文件夹里运行它，它打印自己的全部法则——一页：如何
开始、文件是什么、机器的八条法则。诞生随后把同一份契约写进
区，旁边是文档精确形状的模板和点名机器每扇门的参考页——
完整的手册活在你的项目里，常在手边，而一个区永远教不会
它的机器已经离开的法则。用户文档以英、俄、中三种语言附带；
说明书去找 agent，而不是反过来。

### 视图每次运行重建

状态页和报告在每次运行时从记录重建——从不手编、从不过期
——而如果某一页写不下去，机器拉响警报，而不是悄悄展示旧页。
「下一步做什么」那行在终端和页面上永远一致：在磁盘上的，
就是最新的。

### 诚实的退出码

机器说它工作了（exit 0），就是工作了——在工作内部发现的
问题是数据，不是崩溃。它说调用没有发生（exit 1），就没有
发生。把它包进任何脚本并信任答案。

### 一条命令，没有 flag

没有 flag、没有菜单、没有模式：agent 运行一个词，拿回一行
——下一个动作，指向要碰的文件。唯一的例外是 `--version`，
一个契约从不提及的人类便利。这也是为什么幻觉出 flag 的模型
无法误用这台机器：没有 flag 可供幻觉。

### `done: true` 就是全部签收

AI 如何正式地说「做完了」？它往 inbox 写一行——`done: true`，
别无其他。那行裸文就是签收；机器随后自己重新测量一切。没有
要发明的，没有要排版的，最后一里没有可弄错的。

### 运行之间零足迹

机器只存在于它运行的那一刻：没有后台进程、没有吃内存的
服务、没有窥视你文件的东西——变更检测是运行时的算术，不是
常驻间谍，暂存目录在每次运行结束时清空。运行之间，你的
机器甚至不知道它存在。

### 区是纯文件

一切——言语、每份被接受的 submission、每次 run 的结果、每个
完成——都活在项目内一个隐藏文件夹的纯文件里。复制到另一台
机器，状态逐字节相同；备份它、diff 它、放进版本控制。没有
数据库、没有导出、没有迁移。

### 一行安装，MIT 许可证

把一句话贴给你的 agent：它取回你平台的现成二进制（Linux 与
macOS，x64 与 ARM，校验和已发布）或从源码构建，并放到你的
PATH 上——免费、MIT、无账户、无付费墙。从零到第一个封存
完成，一次会话。

## 诚实的限制

机器逐字节比较真实输出——从不读含义。下面每一项都是已发布
机器的既成事实，直白陈述：

- **言语由 agent 之手进入。**机器从看不见你的聊天；它亲自从
  `demands.md` 取走你的言语并封锁过去，但它无法知道一句从未
  写下的话——而不带新言语的 submission 会签署「没有新言语」，
  这份签名永远留在日志里，显示在状态页上。
- **绿色裁决是形式的完整，不是正确性。**每一行被分解、每条
  row 以钉住的字节保持绿色、树等于 claims 加响亮的豁免——
  机器读不出代码是否做了你的本意；你对 spec 页的那一眼就是
  审计，而它们正是为那一眼构建的。
- **文档是 YAML，而 YAML 会咬伤散文。**含「: 」或逗号的值要
  加引号；多行钉保持一行；缩进中的制表符被拒绝。在最近一次
  实地演练中这是最常见的拒绝（56 次中的 24 次）——每条点名
  自己的位置，没有一条丢数据。
- **一个区、一台机器。**由另一个 punchtape 版本诞生的区被拒绝
  ——归档它、从头开始；没有迁移。
- **仅限 Linux 与 macOS**（amd64/arm64）；rows 经 unix shell
  运行，命令只看得见 PATH、HOME 和 pin。
- **运行按区锁串行。**一次一个 pass 持有区（`run.lock`，由内核
  释放、死亡安全）；并行调用者排队等待——以正在运行的 pass 自身
  命令的死线为限。仅限本地文件系统：网络文件系统没有这个
  承诺。
- **多个 agent 不被协调。**锁串行化的是运行，不是工作：谁提交
  哪一部分是任务主人的决定，工作需要拆成互不重叠的部分，而
  机器是事实的仲裁者——不是 agent 的协调者。
- **永远不要手改日志。**每条记录在加载时被验证；无法复原的，
  按名字拒绝。
