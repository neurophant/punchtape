# Глоссарий
[English](GLOSSARY.md) · **Русский** · [中文](GLOSSARY.zh.md)

Словарь машинной лексики — каждое слово, которое может встретиться
читателю её файлов зоны, её строк терминала и её контракта. Принцип:
если читатель может не понять слово, оно объясняется здесь, простым
языком, с примером или аналогией; `→` указывает на родственные термины
внутри этого словаря. Собственный замкнутый словарь машины мал — id
законов, стояния строк (зелёная, красная, устаревшая), номера строк
желания (W1, W2, …) — всё остальное ниже объясняет этот словарь и мир
непосредственно вокруг него.

A

**Accept** (принятие) — то, что машина делает с документом, прошедшим
каждое правило: его канонические байты и его слитые поведения ложатся
в хранилище объектов, запись подачи ложится в свежую эпоху журнала,
стоящее движется, слот подачи потребляется. Противоположность —
→ refusal. Пример: `inbox.yaml` с одним новым поведением принимается;
следующая строка терминала называет следующий шаг, не принятие, —
принятие живёт в счётчиках `state.md`.

**AGENTS block** (блок AGENTS) — крючок обнаружения машины:
отмеченный маркерами блок внутри `AGENTS.md` рабочего корня,
ограниченный `<!-- punchtape -->` и `<!-- /punchtape -->`,
обеспечиваемый целиком на каждом прогоне. Идентичное содержание
ничего не трогает; изменившееся содержание заменяет себя; чужой файл
без маркеров получает блок в конец. Байты вне маркеров никогда не
трогаются. Аналогия: ярлык библиотечной книги — вклеен внутри
обложки, страницы библиотекарю не принадлежат. → working tree.

**Argument refusal** (отказ от аргументов) — единственная строка,
которой бинарник отвечает на любой запуск с аргументами, кроме
одиночного `--version`: отказ называет закон (вызов не принимает
аргументов) и есть всё действие этого запуска — состояние не
трогается, выход 1. → the call.

B

**Artifacts** (артефакты) — объявленные выходы документа: глобы
относительно корня, называющие файлы, которые работа должна оставить
после себя. Файл дерева, не покрытый ни одним скоупом и не совпавший
ни с одним глобом артефакта, — → uncovered source; совпавший с
артефактом стоит в `state.md` под "artifacts (declared)". Пример:
`artifacts: [out/**]` объявляет выходной каталог сборки.
→ uncovered sources.

**Behavior** (поведение) — одна именованная единица видимого
поведения: id (сегменты `[a-z0-9-]`, соединённые `/`, скажем
`tool/build`), имя в одну строку, → prose автора, необязательный
→ scope, необязательные → covers и хотя бы одна → row. Id — ключ
слияния: подача, повторяющая id, заменяет голову поведения и сливает
его строки. Поведение со строками и без скоупа перезапускается каждый
прогон — честно всегда → stale.

**Birth** (рождение) — акт, создающий инстанс: один атомарный `mkdir`
каталога журнала (ровно один победитель среди параллельных прогонов —
проигравшие продолжают как обычные прогоны), байты желания в
хранилище объектов как первая запись журнала, слот желания потреблён,
и стоящие файлы зоны записаны из канона. Ничто другое никогда не
создаёт инстанс. Аналогия: первый прокол в свежей ленте.
→ wish slot, → instance.

**Brief map** (карта брифа) — учёт желания в одной строке `state.md`:
`brief: <claimed>/<lines> lines; requirements <n> standing, <k>
covered; not-a-requirement: <m>`, за которой каждый маркер прописан и
непокрытые строки желания, когда есть. Та же арифметика, которую
читает гейт желания вердикта, — двух истин не бывает.
→ wish coverage, → registry.

**Build** (сборка) — необязательная объявленная команда корпуса
(шелл-строка). Когда она стоит, она идёт ПЕРВОЙ в каждом прогоне,
прежде любой строки, под тем же законом исполнения, что и строка.
Сборка, выходящая не нулём, зависающая за дедлайном или не стартующая,
красная для всего прогона: каждая строка заморожена — ничего не
исполняется, ничего не движется, кроме собственного записанного в
журнал факта сборки. Объявление сборки в документе заменяет стоящую;
отсутствующее поле сохраняет её. → machine run.

C

**The call** (вызов) — весь интерфейс машины: `punchtape`, без
аргументов, где угодно в рабочем корне или ниже. Каждый ответ сверх
одной строки терминала — файл → zone. → terminal line, → exit code.

**Canon** (канон) — единый встроенный источник всего, что машина
печатает как закон: английский контракт (база и линейка), русское и
китайское зеркала (данные, структурно полные), шаблон документа,
пример, карта законов и правило окружения. Файлы контракта зоны и
шаблон генерируются из него при рождении; пример, который солгал бы о
машине, ломает сборку. → contract, → law-map.

**Canonical bytes** (канонические байты) — одно официальное написание
документа: строгое декодирование в модель, затем канонический
маршалинг (отступ в два пробела, отсортированные ключи отображения,
поля в порядке объявления, написание автора команды сохранено). Два
написания одного содержимого — одно содержимое: машина сравнивает и
журналирует только канонические байты. Пример: переформатированный по
отступам `inbox.yaml` — та же подача, что оригинал.

**Clean environment** (чистое окружение) — база, которую видит каждая
команда машины: ровно имена, которые объявляет канон, — `PATH` и
`HOME`, — взятые из шелла, запускающего машину, плюс → pins зоны, и
ничего больше. Фактически переданный набор вместе с версией машины,
архитектурой и релизом ядра образует → environment hash.

**Completion act** (акт завершения) — знак завершения: `inbox.yaml`,
несущий ровно канонические байты стоящего корпуса (на практике:
`corpus.yaml`, скопированный байт-в-байт в `inbox.yaml`). Не документ —
слот возвращает корпус. Прогон продолжает свои обычные шаги, и шаг
→ verdict решает: каждый гейт зелёный — вердикт записан; чего-то не
хватает — отчёт называет дыры. Считается собственным записанным в
журнал фактом, отдельно от подач. → machine run.

**Contract** (контракт) — весь закон машины одним текстом
(`contract.md` в зоне), печатаемый целиком в терминал при
→ first contact. Пять законов с id — `law:wish` (слот желания и его
пронумерованные строки), `law:document` (единый формат и его законы
слияния), `law:paths` (только пути относительно корня), `law:done`
(акт завершения и гейты вердикта), `law:your-tree` (среда исполнения)
— плюс закон скоупа, закон отказа и форма документа. Русское и
китайское зеркала несут тот же набор законов; правит английский
текст.

**Corpus** (корпус) — стоящий документ: поведения, реестр и команда
сборки, как они стоят после каждой принятой подачи. Его канонические
байты живут как `corpus.yaml` (генерируемый образ, исцеляемый каждый
прогон) и внутри подписи вердикта. Зелёный, когда каждая строка
зелёная, — основание вердикта. → corpus version.

**Corpus version** (версия корпуса) — счётчик принятых подач: каждое
принятие поднимает его на единицу. Вердикт записывает версию, на
которой он провозглашён; строка вердикта в `state.md` называет обе, а
следующая инструкция различает «вердикт стоит на текущей версии» и
«всё зелёное, следующий шаг — акт». → verdict.

**Covers** (покрытия) — заявление поведения о доказательстве: список
id требований, за которые стоят строки поведения. Покрытие обязано
называть требование, стоящее после слияния подачи; отставка требования
требует, чтобы та же подача сняла каждое его покрытие. Стоящее
требование, которое не покрывает ни одно поведение, —
→ orphan requirement, и оно держит вердикт.

D

**Deadline** (дедлайн) — потолок в 300 секунд, под которым идёт каждая
команда машины — каждая строка и сборка одинаково: на дедлайне вся
группа процессов убивается, и факт пишется `timed out after 5m0s`.
Убийца зависаний, никогда не судья медленной работы: машина
ограничивает, как долго одна команда может висеть, никогда — как
долго агент может работать. → process group, → red build freeze.

**Digest** (дайджест) — единица идентичности машины: sha256 точных
байтов, в hex. Одни байты — один дайджест, разные байты — другой
дайджест с подавляющей уверенностью. Дайджесты сводят мир машины
воедино: дайджесты файлов, отпечатки скоупов, доказательства, адреса
объектов, подпись вердикта. Человеческие написания режут его до первых
12 символов. Аналогия: отпечаток пальца — не палец, но достаточно,
чтобы назвать его. → object store, → proof.

**Document** (документ) — единый формат ввода, строго декодируемый
YAML-файл: `notes`, `build`, `remove`, `requirements`,
`not-a-requirement`, `artifacts`, `behaviors` (со `rows`). Документ —
вся таблица или её подмножество: чего он не перечисляет, то не меняет.
→ canonical bytes, → merge, → validation.

**Drift** (дрейф) — производный факт, что дерево сдвинулось под
стоящим вердиктом: прогон, чьи строки стоят красными, пока стоит
вердикт (история называет прогон и ключи красных строк), или живое
поведение, чей текущий отпечаток скоупа отличается от записанного
указателя вердикта (знак `scopes moved` на странице состояния). Ничто
не наблюдает ни за чем — оба знака есть арифметика над записанными в
журнал фактами и свежими отпечатками. Позднейший прогон без красной
строки исцеляет дрейф, тоже названный в истории. → verdict history.

E

**Environment hash** (хэш окружения) — отпечаток того, что видят
команды: версия машины, `GOOS/GOARCH`, релиз ядра и отсортированный
фактически переданный набор `NAME=value` (чистая база плюс
закрепления). Входит в каждое → proof: сессия, изменившая окружение,
сдвигает доказательства — строки устаревают, никогда не зеленея ложно.

**Epoch** (эпоха) — один пронумерованный файл потока журнала
(`epoch-NNNNN.yaml` под `journal/`): записи дописываются в живую эпоху,
по одному YAML-документу за разделителем `---` в начале строки. Подача
ротирует поток прежде, чем её запись ляжет, — записи каждой подачи
живут в своей эпохе; уже свежая эпоха остаётся (ротация никогда не
наслаивает пустые файлы). Загрузка читает каждую эпоху в порядке
номеров. → journal, → torn tail.

**Exit code** (код выхода) — единственный двоичный ответ вызова: 0 —
машина сработала (красные строки — данные, не ошибка); 1 — вызова не
произошло (повреждение зоны, журнал, который не смог загрузиться,
машинная запись, которая не смогла лечь).

**Expect** (ожидание) — требование строки к тому, что команда
оставляет после себя: любая смесь `rc` (точный код выхода; отсутствие
= 0), `out` (stdout: точные байты или подстрока за префиксом
`contains: `) и `files` (пути относительно корня, читаемые после
прогона, те же два варианта сопоставления). Должно стоять хотя бы одно
поле — пустой expect отклоняется. Сравнение чистое: никакого толкования
нигде.

F

**First contact** (первый контакт) — запуск без `.punchtape` в рабочем
каталоге или выше: машина печатает весь контракт и выходит 0, ничего
не создавая. Полностраничное исключение терминала — файлового канала
ещё нет, поэтому сам закон есть ответ.

**Fold** (свёртка) — перестройка настоящего из прошлого: все записи
журнала, от старых к новым, переигрываются в → standing — рождения
фиксируют цель, подачи движут корпус, прогоны ставят факты строк,
вердикты стоят, отказы и завершения считаются. Одни и те же записи
всегда сворачиваются в одно и то же стоящее. Аналогия: повторное
проигрывание перфоленты с начала — лента есть истина, память машины
производна.

G

**Goal** (цель) — зафиксированное желание инстанса: байты желания как
объект с адресацией по содержимому, записанный при рождении со своим
дайджестом — неизменный навсегда. Страница состояния показывает дайджест
и адрес объекта; каждая строка желания и каждая цитата маркера
производны от этих байтов, поэтому нумерация не может дрейфовать.

**Green** (зелёный) — стояние строки: она исполнилась, и каждое её
ожидание выдержало (список фактов поломки пуст). Зелёная строка, чьё
→ proof всё ещё стоит, → kept green — не исполняется повторно. Корпус
зелёный, когда каждая строка зелёная; только зелёный свежий корпус
может закрыть вердикт.

H

**Hash cache** (кэш хэшей) — `cache/hashes.yaml`: ускоритель
`(path, size, mtime)` → дайджест обхода дерева, каждая запись помечена
законом дайджеста, по которому она сделана. Тронутый файл честно
перевычисляется; испорченный или отсутствующий кэш читается как
пустой; записи с чужим тегом выпадают и перевычисляются, вместо того
чтобы лгать. Сбрасывается на диск один раз за прогон. Удали его —
следующий прогон перевычислит те же числа: ускоритель, никогда не
источник истины. → scope fingerprint, → tree walk.

**Holes** (дыры) — строки желания, которые не заявляет ни один
диапазон требования и ни один маркер: `state.md` прописывает их
(`uncovered brief lines: W…`), и вердикт отказывает на них
(`not yet — the wish lines W… stand uncovered by any
requirement or marker`). Написание диапазона, которое не разбирается, или число вне
вселенной желания не заявляет ничего — строки, которые оно называет,
остаются честными дырами. → wish coverage.

I

**Inbox (the submission slot)** (слот подачи) — `inbox.yaml`,
единственный входной файл зоны. Его присутствие означает: ждёт подача —
документ, чтобы декодироваться, валидироваться и приняться, — или
→ completion act — или → refusal, который ничего не меняет (байты
остаются, автор исправляет названное место и запускает снова). Его
отсутствие — обычное состояние. Всё, что входит в машину, входит через
этот один файл.

**Instance** (инстанс) — одна задача машины: рабочий корень, его зона
`.punchtape` (журнал, объекты, представления, слоты) и блок AGENTS в
корне. Рождается один раз, никогда не умирает; по-настоящему новая
задача — новое желание в свежем каталоге. → birth, → zone.

J

**Journal** (журнал) — единственный источник истины: поток только
дописываемых записей под `journal/`; каждая подача открывает свежую
эпоху. Шесть видов записей — рождение, подача, прогон, вердикт, отказ,
завершение — каждый несёт ровно свой полезный груз, никаких настенных
часов нигде: порядок — место записи, идентичность — её байты. Журнал
одной истории байт-в-байт одинаков на каждой машине. Каждый другой
файл зоны — его генерируемый образ. → fold, → standing.

K

**Kept green** (остаётся зелёной) — зелёная строка, чьё записанное
доказательство равно текущему доказательству: строка не исполняется,
не читается, не трогается — её записанная зелёность стоит.
Вся экономика машины: неизменные входы ничего не стоят. → proof, → stale.

**Knowledge** (знания) — файл памяти зоны `knowledge.md`: каждая
заметка каждой принятой подачи ровно один раз (пронумерованная, с её
→ tags на её строке), индекс тегов и записи → lesson,
сгруппированные по причине. Генерируется из журнала; сами заметки
никогда не толкуются.

L

**Law ids** (id законов) — пять названных законов контракта, словарь
каждого отказа: `law:wish`, `law:document`, `law:paths`, `law:done`,
`law:your-tree`. Отказ всегда цитирует один — названное правило и
контракт всегда говорят об одном и том же. → refusal.

**Law-map** (карта законов) — таблица чётности канона: каждое правило
валидации привязано к закону, который печатает контракт, и каждый
цитируемый закон — из печатаемых контрактом. Что применяется, то
печатается; что печатается, то применяется.

**Lesson** (урок) — одна зафиксированная краснота как чистые данные:
класс причины, ключ строки, факты поломки, байты строки
до и после (байты «до» восстанавливаются из объектов поведений журнала
по дайджесту) и два номера прогона. Записан самой записью прогона —
ноль токенов любой модели. Текущая красная строка, чья причина имеет
урок, получает указатель из `state.md`. Пример: строка красная на
`exit: got 1, want 0` на прогоне 4, зелёная на прогоне 5 — урок несёт
обе строки и оба номера.

M

**Machine at birth** (машина при рождении) — версия машины, которую
несёт запись рождения: собственный факт происхождения инстанса,
печатаемый страницей состояния (`machine at birth:`); инстанс, чья
запись его лишена, говорит `(not recorded)`. Версия также входит в
хэш окружения, поэтому новая машина честно аннулирует старые
доказательства. → birth, → environment hash.

**Machine run** (прогон машины) — одно исполнение вызова после
рождения: шаг подачи, сборка, снятие отпечатков, исполнение устаревших
строк, журнал, вердикт, рендер. Номер прогона (→ run number) считает
только прогоны, менявшие факты (сборка прошла или строка
исполнилась); прогон, который измерил и отрендерил, не меняет ничего.

**Marker (not-a-requirement)** (маркер) — отставка в реестре: строки
желания, объявленные ничего не требующими, с собственными словами
строк, процитированными дословно рядом с причиной. Цитата обязана
совпадать с собственным текстом желания точно — отставка спроса
требует копировать его в подписанный корпус; отметка не может быть
тихой. Пример: строка-заголовок помечена `quote: "a counter", reason: the wish's title names the work, it
demands nothing`.

**Merge** (слияние) — законы подачи: поведения сливаются по id
(перечисленная голова заменяется целиком — имя, проза, скоуп, covers —
строки сливаются по → run key); требования сливаются по id так же;
списки маркеров и артефактов заменяются целиком, когда подача их
несёт; `remove` отставляет стоящие id; отсутствующее поле ничего не
меняет. Экономия: число подач никогда не влияет на цену — неизменённые
строки не пересылаются.

**Next instruction** (следующая инструкция) — единственный императив
машины, тот же текст в строке терминала и в строке `next:` в
`state.md`: красная сборка говорит исправить сборку; пустой корпус
говорит подать первый документ; красные строки говорят прочитать
отчёт и исправить; устаревшие строки говорят запустить снова; вердикт,
стоящий на текущей версии корпуса, говорит показать `state.md`
человеку; всё зелёное говорит скопировать `corpus.yaml` в
`inbox.yaml` и запустить, чтобы записать вердикт. В каждом состоянии,
в котором может стоять машина, ровно одна инструкция — двух истин не
бывает.

**Note** (заметка) — свободный текст, который несёт документ
(`notes: [{text: …}]`). Машина никогда не толкует заметку: она хранит
канонические байты документа, а рендер перечисляет заметки с
механическими → tags. Канал для людей, не канал в машину.

O

**Object store** (хранилище объектов) — хранилище с адресацией по
содержимому под `journal/objects/`: имя объекта — sha256 его байтов;
его файл — `<first two hex>/<remaining sixty-two>`. Одинаковые байты
хранятся один раз — дедупликация по построению; каждая запись
перечитывается и проверяется, каждое чтение проверяет свой дайджест.
Байты желания, канонические байты каждого принятого документа и
канонические байты каждого слитого поведения живут здесь, неизменные.
→ digest.

**Orphan requirement** (требование-сирота) — стоящее требование,
которое ни одно стоящее поведение не называет в своих covers. Держит
вердикт (`not yet — the requirements …
stand uncovered by any behavior's covers`). → covers.

P

**Pins** (закрепления) — необязательные объявления окружения зоны:
файл `env`, один `KEY=VALUE` на строку, ключ `[A-Za-z_][A-Za-z0-9_]*`,
без `export`, без кавычек, без абсолютных путей (закрепление ездит с
деревом). Комментарии и пустые строки проходят, замыкающий перевод
каретки терпится. Строка любой другой формы — громкий отказ,
называющий файл, строку и закон. Закрепление побеждает чистую базу по
имени. Пример: `TOOLS=tools/bin` — значение может быть относительным
путём, никогда абсолютным.

**Process group** (группа процессов) — дисциплина запуска: каждая
команда машины идёт в своей группе, и всё, что она оставила живым
(серверы, воркеры, порождённое шеллом), убивается с группой — сигнал
убийства группе и процессу, затем ограниченное ожидание фактической
смерти. Остатки строки никогда не переживают строку.

**Proof** (доказательство) — отпечаток зелёной строки: sha256 по
каноническим байтам строки, → scope fingerprint её поведения и
→ environment hash. Пока записанное доказательство равно текущему,
строка → kept green; движение любого из трёх делает её → stale.
Аналогия: сургучная печать на строке, её входах и её окружении —
сломай любое, печать сломается.

**Prose** (проза) — собственное описание поведения словами автора: что
получает пользователь и почему. Обязательна и непуста; переносится
дословно на страницу spec поведения. Машина проверяет присутствие,
никогда качество — чтение есть дело человека.

R

**Red** (красный) — стояние строки: она исполнилась, и сломалось хотя
бы одно ожидание (факты поломки, записанные в журнал как измеренные,
есть причина). Красные строки группируются по причине в отчёте. Закон
пропуска не различает цвета: стоящая красная перезапускается ровно
тогда, когда движется её → proof — её входы изменились — тот же закон,
что держит зелёную строку зелёной; но стоящая красная никогда не
сходит за готовое, потому что → verdict читает статус факта, никогда
не одни доказательства. Красное под стоящим вердиктом — → drift.

**Red build freeze** (заморозка красной сборки) — закон, что сломанная
сборка останавливает всё: ни одна строка не исполняется в том прогоне,
ни один факт строки не движется; запись прогона несёт только факт
сборки, а следующая инструкция говорит `build red`.

**Refusal** (отказ) — ответ машины на сломанную подачу: одна строка на
сломанное правило — точное поле, → law ids, измеренный факт. Байты
подачи ничего не пишут; сам отказ записывается в журнал как
собственный факт машины и считается на `state.md`; документ остаётся в
`inbox.yaml`, автор исправляет названное место и запускает снова.
Пример: `behaviors[0].rows[1].expect: the expect is empty —
name rc, out or files (law:document)`. → validation.

**Registry** (реестр) — учёт желания корпусом: требования (каждое со
своими диапазонами строк желания), маркеры и объявленные артефакты.
Сливается по законам подачи; целиком в → registry digest вердикта.
→ brief map.

**Registry digest** (дайджест реестра) — sha256 по каноническим байтам
требований и маркеров вместе — весь учёт желания, запечатанный одним
дайджестом и переносимый записью вердикта.

**Report** (отчёт) — `report.md`: вся картина последнего события,
менявшего факты, — для прогона строка сборки, число зелёных и каждая
красная строка, сгруппированная по причине поломки, плюс заметки
вердикта, когда говорил акт завершения; для отказа строка на отказ и
указатель исправления. Пишется целиком, когда движется; прогон, ничего
не изменивший и ничего не закрывший, оставляет предыдущий отчёт
стоять. → refusal, → verdict, → views.

**Requirement** (требование) — один спрос желания: id (`R` плюс буквы,
цифры и точки — хвост может быть пуст, скажем `R1`) и строки желания,
которые он занимает (W-диапазоны). Сливается по id; отставляется только
явным `remove`, который также снимает каждое его покрытие. Желание
учтено целиком, когда каждая строка сидит внутри диапазона какого-либо
требования или за маркером.

**Row** (строка) — один исполняемый контроль внутри поведения: одна
команда (`run` — шелл-строка или список argv) и её → expect.
Канонические байты команды — → run key строки и часть её → proof;
место строки в поведении — её ключ журнала (`<behavior id>/<index>`).
Строки — всё, чем поведение доказывает.

**Run key** (ключ команды) — канонические байты команды, ключ слияния
строки: поданная команда, которая стоит, заменяет всю эту строку на
месте; новая дописывается; неперечисленные строки стоят. Переписанная
заново команда — новая; стоящая стоит. Пример: `./tool src out` и
`["./tool", "src", "out"]` — два написания одной команды.

**Run number** (номер прогона) — счётчик меняющих факты прогонов.
`run <N>` строки терминала, заголовки отчёта, состояния, знаний и spec
называют одно и то же число. Отказ не стоит номера прогона — он
считается собственным счётчиком.

S

**Scope** (скоуп) — объявленная зависимость поведения: глобы
относительно корня, называющие файлы, на которых поведение стоит.
Дайджесты покрытых файлов образуют → scope fingerprint; изменение
внутри скоупа делает строки поведения устаревшими. Файлы, не покрытые
ни одним скоупом, — → uncovered sources или объявленные артефакты.
Поведение со строками и без скоупа перезапускается каждый прогон —
всегда давай строкам скоуп.

**Scope fingerprint** (отпечаток скоупа) — дайджест по
отсортированным парам поведения `(path, file-digest)` — содержимое его
карты скоупа. Файл скоупа, которого не существует, пишется `absent`:
карта называет, что обязано стоять, отпечаток видит, что стоит.

**Scope glob** (глоб скоупа) — написание скоупа: шаблон через слэш
относительно корня, сегменты которого несут `[A-Za-z0-9-._*?[]`;
сегмент `**` поглощает ноль и более каталогов, `*`/`?`/`[...]`
матчатся внутри одного сегмента. Пример: `src/**` покрывает всё под
`src/` (и саму `src/`); `*.md` покрывает маркдаун корня.

**Signature (the verdict's)** (подпись вердикта) — sha256 по
каноническим байтам корпуса плюс, на каждое поведение в порядке
сортировки id, `\0 id \0
scope fingerprint`: спецификация и точное
состояние дерева, на котором она провозглашена, одним дайджестом.
Показывается короткой (12 символов) на странице состояния и в истории
вердиктов.

**Spec tree** (дерево spec) — каталог представлений `spec/`:
`index.md` плюс одна маленькая страница на каждое живое поведение (id
и имя, номер прогона, проза дословно, скоуп и на строку команда,
ожидание и стояние доказательства с его коротким дайджестом). Страницы
отставленных поведений удаляются — дерево есть образ стоящего корпуса,
ничего больше.

**Stale** (устаревший) — стояние строки: её → proof сдвинулся (её
байты, файлы скоупа её поведения или окружение) — или она никогда не
исполнялась — или её поведение не объявляет скоуп. Устаревшие строки
исполняются на следующем прогоне; инструкция считает их
(`N row(s) stale — run again to execute
them`).

**Standing** (стоящее) — настоящее, перестроенное из журнала свёрткой
(→ fold): цель, версия корпуса и сборка, реестр, поведения и их
порядок, факты строк, номер прогона, вердикт, подачи, счётчики отказов
и завершений, уроки. Всё, что машина решает, она решает по стоящему —
а стоящее всегда выводимо из одних записей.

**State page** (страница состояния) — `state.md`: стоящее на одной
странице — цель и адрес желания, карта брифа с каждым маркером и
непокрытыми строками, версия корпуса, три счётчика, машина при
рождении, вердикт с его знаком scopes-moved и историей, строка на
поведение, объявленные артефакты и непокрытые исходники, счётчики
знаний и `next:` — тот же текст, что строка терминала.
→ standing, → views.

**Submissions** (подачи) — принятые документы, считаемые на `state.md`
рядом с отказанными и завершёнными — три отдельных экономики:
документы, взятые слотом; подачи, им отклонённые; акты завершения,
закончившие работу.

T

**Tags** (теги) — механическая группировка заметок: пересечение
собственных слов заметки со → vocabulary инстанса (слова желания и
стоящего корпуса — строчные последовательности букв и цифр длиной от
двух символов). Каждая заметка несёт свои теги в своей строке; индекс
отображает каждый тег в номера его заметок. Только группировка —
никогда проверка; никакой семантики нигде.

**Template** (шаблон) — `template.yaml`, генерируемый из канона при
рождении: форма документа с обучающими комментариями. Скопируй,
отредактируй, подай как `inbox.yaml`. Документ, который декодируется,
но ломает правило, всё равно отклоняется — шаблон учит форме,
валидация держит закон.

**Terminal line** (строка терминала) — одна строка вывода вызова при
успешном прогоне: `punchtape: run <N> — <instruction>`. Инструкция
называет файл, который тронуть, и есть тот же текст, что строка
`next:` в `state.md`. Исключения: первый контакт печатает весь
контракт; состояние «инстанса ещё нет» печатает свою одну
строку-инструкцию; вызов, который не может произойти, отвечает своей
единственной строкой ошибки — выход 1. Всё остальное, что машина может
сказать, живёт в файлах зоны.

**Torn tail** (рваный хвост) — запись журнала, оборванная посреди
записи на диск (краш, потеря питания). Она не ослепляет машину: целые записи
грузятся, рваные байты карантинятся в сайдкар (`<epoch>.torn`), и файл
эпохи перестраивается байт-в-байт из целых записей. Кусок, который не
разбирается вне конечной позиции, — повреждение руками — честная
ошибка. → epoch.

**Tree walk** (обход дерева) — единственный способ машины видеть
рабочее дерево: один упорядоченный обход, пропускающий зону
(`.punchtape`) в рабочем корне и служебные каталоги контроля версий
(`.git`, `.hg`, `.svn`) по имени, где бы они ни стояли, собирающий
пути файлов относительно корня. Обход питает отпечатки скоупов и
раскладку непокрытых файлов. Машина никогда не читает содержимое
дерева как код — только как байты для дайджеста и команды для запуска.

U

**Uncovered sources** (непокрытые исходники) — файлы дерева, которые
не покрывает ни один скоуп и не объявляет ни один глоб артефакта
(кроме собственного файла блока AGENTS). Прописаны по одному на строку
в `state.md`; единственный непокрытый исходник держит вердикт
(`not yet — the sources … stand uncovered`). Дыры машины — видимые
факты: покрой их скоупом или объяви.

V

**Validation** (валидация) — весь набор правил, который документ
проходит перед принятием: алфавиты id и уникальность, грамматика
W-диапазонов против вселенной желания, причины маркеров и дословные
цитаты, законные глобы и пути относительно корня, covers, называющие
стоящие требования, строки с ожиданиями, remove, называющий стоящие
id, — плюс проверка висячих покрытий на поведения, переживающих
неперечисленными. Каждый отказ называет поле, факт и id закона.
→ refusal.

**Verdict** (вердикт) — провозглашение машиной завершённости,
записываемое только при → completion act и только когда каждый гейт
стоит: корпус непуст; каждая строка зелёная на текущих отпечатках;
желание учтено целиком (каждая строка внутри диапазона требования или
за маркером); ни одного требования-сироты; ни одного непокрытого
исходника. Запись несёт номер, версию корпуса, → signature,
→ registry digest, указатель скоупа каждого поведения и номер
закрывающего прогона; рядом ложится запись завершения. Только
дописывается — новый вердикт никогда не переписывает старый. Чего-то
не хватает — `not yet` плюс строка на класс дыр в отчёте.

**Verdict history** (история вердиктов) — производная хроника страницы
состояния: каждый записанный вердикт (прогон, номер, версия, короткая
подпись); каждый → drift (прогон с красными строками под стоящим
вердиктом, с красными ключами); каждое исцеление (первый позднейший
прогон без красной строки). Чего журнал не несёт, того история не
говорит.

**Version flag** (флаг версии) — `punchtape --version`, ровно это
написание и одно в строке: печатает `punchtape <version>` и выходит 0,
прежде чем тронуто какое-либо состояние, — единственное удобство для
человека; контракт никогда его не упоминает. → the call, → exit code.

**Views** (представления) — генерируемые файлы зоны: `state.md`,
`report.md`, `knowledge.md`, дерево spec, `corpus.yaml`. Образы журнала
— переписываются целиком при изменении содержимого, не трогаются без
изменения; представление, которое не может лечь, — громкая ошибка
(устаревшее лицо есть ложь).

**Vocabulary** (словарь) — собственный набор слов инстанса: каждое
слово байтов желания и канонических байтов стоящего корпуса — строчная
последовательность ASCII-букв и цифр длиной два символа и более.
→ tags заметки — механическое пересечение её слов с этим набором;
никакой семантики нигде — слово, которого инстанс никогда не нёс, не
отвечает ничего.

W

**W range** (W-диапазон) — единственное написание строк желания: `W<n>`
или `W<a>..W<b>` по возрастанию, через запятую (`W1..W4, W9`). Номера
называют непустые строки желания в порядке файла, зафиксированные при
рождении навсегда; диапазоны брифа требований и строки маркеров ездят
на этой грамматике, и машина прописывает множества номеров обратно в
ней со схлопнутыми подряд идущими (`W19, W23..W25`). → wish,
→ requirement, → marker.

**Wish** (желание) — хотение человека, дословно, положенное в
`wish.md` до рождения. Рождение фиксирует его навсегда как → goal и
нумерует его непустые строки W1…Wm в порядке файла — номера никогда не
меняются, каждый диапазон требования и каждый маркер цитирует их.
Размер желания решает размер корпуса — не вкус.

**Wish coverage** (покрытие желания) — арифметика по вселенной желания:
какие строки заявляет диапазон какого-либо требования или диапазон
какого-либо маркера, а какие стоят как → holes. Одна функция питает
карту брифа страницы состояния и гейт желания вердикта — двух истин не
бывает.

**Wish slot** (слот желания) — `wish.md`, входной файл до рождения.
Присутствует без журнала — следующий прогон рождает инстанс и
потребляет слот; отсутствует — машина отвечает своей одной
строкой-инструкцией и ничего не создаёт. Слот мёртв после рождения:
цель зафиксирована, и ничто другое никогда не создаёт инстанс.

**Working root / working tree** (рабочий корень / рабочее дерево) — каталог, несущий зону
(вызов находит её в своей стартовой точке или
выше) и всё рядом с ней. Дерево — территория агента: машина обходит
его, дайджестирует его, исполняет в нём команды — и никогда не читает
его содержимое как код.

Z

**Zone** (зона) — `.punchtape/`, единственный каталог, которым владеет
машина: слоты (`wish.md`, `inbox.yaml`, `env`), генерируемые файлы
стоящего (`corpus.yaml`, `state.md`, `report.md`, `knowledge.md`,
`spec/`), журнал со своими объектами и собственные `cache/` и `tmp/`
машины. Никогда не редактируется руками; одна запись стоит вне её —
→ AGENTS block в рабочем корне.
